#+title: Org TeXmacs
#+author: aRenCoco

Org TeXmacs is an Org-first mathematical-document AST framework.  Native Org
AST represents document structure and semantics; native TeXmacs STM trees
represent mathematical expressions; identity-based islands connect them.
This is one logical structure, without a third canonical AST.  Org buffers
remain the canonical authoring input, with no external =.tm= file required.

The independent core constructs owned models, exposes readable structure,
copies snapshots, replaces STM subtrees and generates normalized Org text or
editable buffers.  Complete models expose parsed STM trees; source discovery
and other construction intermediates can defer parsing.  Structural validity,
syntax expressibility and serialization support are separate contracts.
The native expression trees are structural representations, not a formal
mathematical semantics system.

=ox-texmacs= is a standard Org Export backend.  Org prepares the final AST and
INFO; the adapter owns Org structure and native STM islands, then uses pure
structural lowering and native consumers for TeXmacs/PDF.
Shared ownership does not make a bare =org-texmacs-model= a supported argument
to the existing =org-texmacs-document= prepared-input API.  Use the established
export preparation entries for that consumer.
Block caching, on-demand fragment parsing, Scheme fontification and source
editing remain available independently of whole-document model construction.

Document conversion supports basic inline markup, self-contained URI links,
plain local file links with captured resource context,
same-document headline/ID and dedicated-target links, anonymous and named
footnotes, standard Org Cite through the supported CSL processor,
list/container structures, rich metadata,
relative headline sectioning, a static filtered TOC, static preformatted
blocks, named/captioned basic rectangular tables and TeXmacs islands, as specified below.
Formal statements, raw STM equations and explicit figure/table wrappers support
bounded caption and same-document reference semantics.  Embedded STM has Scheme
fontification and source editing through Org's existing edit workflow.
Independent consumers provide native =.tm= serialization, new-file saving and
PDF rendering.  The optional =ox-texmacs= frontend connects these consumers to
Org's export dispatcher, with local output naming/reexports, subtree/region/
narrowing scopes and standard Org export configuration.  GUI preview, cross-file
reference resolution and live incremental Org/TeXmacs synchronization are outside the current
support boundary.
Org's source buffer and live AST remain unchanged.

* Requirements
- Emacs 31.1 or later and Org 9.8 or later, as declared by the package.
- TeXmacs with headless mode (=-H=) and its embedded Scheme runtime.
- Unix-domain socket support in both Emacs and TeXmacs.

Recorded regressions on =x86_64-linux= used Emacs 31.1, Org 9.8.10 and
TeXmacs 2.1.5.  Nix selects dependency revisions from the project's =flake.lock=;
an existing local Org installation does not select those versions.  The package's
Org 9.8 minimum passed a separate API/signature and strict compilation check
for the earlier v0.5.0 implementation.  That result does not establish minimum-
version behavior for the new model APIs.  Complete v0.6.0 ERT and native behavior
regressions use Org 9.8.10; they have not been run on Org 9.8.  Other platforms
have not been validated.

Org-roam and the three extensions described under [[*Optional real Org extension integration][Optional real Org extension integration]]
are optional test dependencies, not package runtime requirements.

The Scheme service runs inside TeXmacs; a separate =guile= executable is
not required to use the package.  Nix test drivers invoke Emacs directly.

* Loading the package
** From a source checkout
Keep all =org-texmacs*.el= files, =ox-texmacs.el= and
=org-texmacs-worker.scm= together in the checkout's =lisp/= directory.
Add that directory to Emacs's =load-path=, replacing
the example path below:

#+begin_src emacs-lisp
  (add-to-list 'load-path "/path/to/org-texmacs/lisp/")
  (require 'org-texmacs)
#+end_src

By default, Emacs locates =texmacs= through =exec-path=.  To select a specific
executable, set =org-texmacs-program= before the first worker operation:

#+begin_src emacs-lisp
  (setq org-texmacs-program "/path/to/bin/texmacs")
#+end_src

Run =M-x org-texmacs-check-setup= to inspect the required capabilities.
The Lisp function returns =(BOOL . REPORT)=.  It checks API and executable
existence; it does not start TeXmacs or test socket connectivity.

** With Nix
From the repository root, launch the development environment's Emacs:

#+begin_src sh
  nix develop --no-write-lock-file --command emacs
#+end_src

This Emacs includes the package and its Lisp dependencies.  The development
environment also includes TeXmacs.  Evaluate =(require 'org-texmacs)= before
using the API.

The flake exposes six named package outputs and no default package:

|----------------------------------------------+---------------------------------------------------------------|
| =packages.org-texmacs=                       | Lisp package with the adjacent Scheme service                 |
| =packages.emacs=                             | Emacs with Org TeXmacs and its Lisp dependencies              |
| =packages.texmacs-fandol=                    | TeXmacs with explicit Fandol Chinese fonts                    |
| =packages.texmacs-with-gotor-support=        | TeXmacs with native GoToR actions for local PDF file links    |
| =packages.texmacs-fandol-with-gotor-support= | TeXmacs with both Fandol fonts and GoToR support              |
| =packages.org-texmacs-examples=              | English and Chinese examples as native TeXmacs files and PDFs |

The GoToR package currently requires TeXmacs 2.1.5.  Its build checks the reviewed
link-action branch before applying a zero-fuzz patch.  Unrelated renderer changes
are allowed; changed link dispatch requires review.

The Lisp package sets the default =org-texmacs-program= to TeXmacs's absolute
Nix store path.  TeXmacs is therefore part of its runtime closure; the installed
package does not depend on finding it in =exec-path=.  Building
=packages.org-texmacs= alone does not configure an existing Emacs installation.
The development shell uses the same Emacs wrapper as =packages.emacs=.
It also provides =texmacs-fandol-with-gotor-support= on =PATH=; this does not
override the Lisp package's built-in TeXmacs path.  To use that renderer from
the shell's Emacs, set =org-texmacs-program= to its executable path before the
first worker operation.  The compiled examples select it through their own
package override, as described below.

Package definitions live under =pkgs/=, with Lisp supplied explicitly from
=lisp/= and example sources collected from =pkgs/org-texmacs-examples/sources/=
using =lib.fileset.toSource=.  The flake uses =personal-nixpkgs=
for flake, package-overlay and test-check composition; its =nixpkgs= input follows
the project's =nixpkgs=.

Two public overlays allow downstream package sets to select these additions:

| Overlay                  | Addition                     |
|--------------------------+------------------------------|
| =overlays.emacsPackages= | =emacsPackages.org-texmacs=  |

Both are nixpkgs overlays, applied when constructing a nixpkgs package set.

** With use-package
Choose one of the following installation paths.  Configure the required Org
version before loading Org TeXmacs; these examples do not select or replace
your Org installation.  They assume =use-package= is already available.

For a source checkout, replace the directory below with its absolute path:

#+name: example-use-package-local
#+begin_src emacs-lisp
  (use-package org-texmacs
    :load-path "/path/to/org-texmacs/lisp/"
    :ensure nil
    :demand t)
#+end_src

For a package already made available on =load-path=, including a configured
Nix installation, omit =:load-path=:

#+name: example-use-package-installed
#+begin_src emacs-lisp
  (use-package org-texmacs
    :ensure nil
    :demand t)
#+end_src

=:ensure nil= prevents =use-package= from asking =package.el= to install the
package, even when =use-package-always-ensure= is enabled.  If your initialized
straight integration uses =straight-use-package-by-default=, also add
=:straight nil= to either declaration above to keep that installation path.
Do not add that keyword when straight integration is unavailable.

*** Installing with straight.el
After initializing straight.el and its use-package integration, use this

#+name: example-use-package-straight
#+begin_src emacs-lisp
  (use-package org-texmacs
    :straight
    (org-texmacs :type git :host github
                 :repo "ren-lingyu/org-texmacs"
                :files ("lisp/org-texmacs*.el"
                        "lisp/ox-texmacs.el"

    :ensure nil
    :demand t)
#+end_src

The =:files= entry is essential: the Scheme service must be installed next
to the Lisp libraries, not left only in the source repository.  Installing
with straight may clone repositories and write build files.  It does not
install the TeXmacs executable; install TeXmacs separately and make it
available through =exec-path= or =org-texmacs-program=.

This recipe does not by itself pin a release.  Use straight's
[[https://github.com/radian-software/straight.el#version-lockfiles][version lockfiles]] to record the selected revision for reproducibility.
For straight setup and recipe details, consult its
[[https://github.com/radian-software/straight.el#integration-with-use-package][use-package integration documentation]].

*** Loading and optional configuration
=:demand t= loads the Lisp package immediately, even if use-package normally
defers loading.  It does not start TeXmacs.  The first block cache miss or
fragment tree request starts the worker, as does document island parsing
or opening a native session; source discovery alone does not.

The core exposes ten customizable variables, shown in this example.  The
optional =ox-texmacs= frontend adds =org-texmacs-export-menu-keys=, described
under [[*Org export dispatcher][Org export dispatcher]].  Its old
=org-texmacs-export-discover-bibliography= flag is obsolete; leave it nil.
The example assumes the package is already on =load-path= and explicitly sets
the source/straight defaults.  For a different installation path, copy its
=:custom= section into the corresponding declaration above rather than
adding a second declaration.  The straight opt-out guidance above still applies.

For a Nix installation, omit the =org-texmacs-program= entry to preserve
the packaged absolute TeXmacs path.  Setting it to ="texmacs"= overrides
that default and requires the executable to be found through =exec-path=.

#+name: example-use-package-custom
#+begin_src emacs-lisp
  (use-package org-texmacs
    :ensure nil
    :demand t
    :custom
    (org-texmacs-program "texmacs")
    (org-texmacs-worker-start-timeout 60)
    (org-texmacs-worker-request-timeout 10)
    (org-texmacs-format-headline-function
     #'org-texmacs-format-headline-default-function)
    (org-texmacs-document-style '("generic"))
    (org-texmacs-document-initial nil)
    (org-texmacs-pdf-file-links-as-absolute nil)
    (org-texmacs-link-org-files-as-pdf t)
    (org-texmacs-edit-mode 'scheme-mode)
    (org-texmacs-fragment-tags
     '("math" "equation" "equation*" "eqnarray" "eqnarray*"
       "align" "align*" "gather" "gather*" "eqsplit" "eqsplit*")))
#+end_src

Both timeouts are positive numbers in seconds: =org-texmacs-worker-start-timeout=
limits the startup wait, and =org-texmacs-worker-request-timeout= limits the
wait for a response to an individual request.

=org-texmacs-document-style= is a nonempty list of TeXmacs style identifier
strings.  =org-texmacs-document-initial= is an alist from unique nonempty
environment identifier strings to STM/source-semantic text strees.  The
default style is =("generic")= and the default initial environment is empty.
These values are copied into each prepared input and document result; changing
them affects only later buffer conversions.  A native session applies the
captured style and initial environment together with that result's body.

Use an absolute executable path instead of ="texmacs"= when needed.  Set
it before the first parse; changing it does not replace an existing worker.
The tag list preserves all 11 default entries.  Replace it with ='("math")=
for math-only discovery, or =nil= to disable fragment discovery without
disabling block parsing.  Obtain fresh spans after changing the tag list.

After loading, run =M-x org-texmacs-check-setup=.  Missing executables are
reported there and checked again before a worker is started.  A passing
setup check confirms basic capabilities, not successful headless startup
or socket communication; an actual parse checks those paths.

* Block formulas
Write official STM/Scheme data in an Org special block:

#+begin_src org
  ,#+begin_texmacs
  (with "mode" "math"
    (concat "x+" (frac "1" "2")))
  ,#+end_texmacs
#+end_src

Place point on the =#+begin_texmacs= line and evaluate:

#+begin_src emacs-lisp
  (org-texmacs-tree (org-element-at-point))
#+end_src

The result is an Org-compatible pseudo tree, with TeXmacs tags such as =with=,
=concat= and =frac=.  Access it with Org functions such as =org-element-type=,
=org-element-contents= and =org-element-map=.  Its children have =:parent=
links; the root is detached from the source block.  An atomic STM string
returns a string without text properties.

This self-contained example demonstrates traversal and a cache hit:

#+name: example-tree
#+begin_src emacs-lisp
  (progn
    (require 'org-texmacs)
    (with-temp-buffer
      (org-mode)
      (insert "#+begin_texmacs\n"
              "(with \"mode\" \"math\" (concat \"x+\" (frac \"1\" \"2\")))\n"
              "#+end_texmacs\n")
      (goto-char (point-min))
      (let* ((block (org-element-at-point))
             (tree (org-texmacs-tree block)))
        (list (org-element-map tree '(with concat frac) #'org-element-type)
              (eq tree (org-texmacs-tree block))))))
  ;; => ((with concat frac) t)
#+end_src

* Block source and cache contract
=org-texmacs-tree= expects a current TeXmacs special-block element from the
current buffer.  Its body must be accessible under the current narrowing.
The Org wrapper name is case-insensitive: =#+begin_texmacs=,
=#+BEGIN_texmacs=, =#+begin_TEXMACS= and =#+BEGIN_TEXMACS= are equivalent,
as are mixed-case names and their closing markers.  The original source and
Org block type spelling are preserved.  STM contents and inline fragment tag
names retain their case-sensitive native meaning.
After editing, obtain the element again; do not retain a block from an old
parse or pass an element from another buffer.

The function reads the raw body using Org's contents bounds.  It preserves
source whitespace and leaves the buffer text and native special-block
representation intact.  Derived trees are stored with Org's custom cache
API, using its default invalidation rules.

Treat returned trees as read-only: a cache hit returns the same object.
Body edits invalidate the derived value.  Unrelated edits, including changes
before a block, may also invalidate it; the cache is best-effort and does not
provide a persistent block identity.  No real-time Org edit hooks are used.

If text changes while waiting for the worker, the call reports an error and
does not cache the old result.  Obtain a fresh block and call again.

* Fragment formulas
** Usage
Write fragments directly in paragraph text using a configured TeXmacs root:

#+begin_src org
  A (math (frac "1" "2")) B

  An equation (equation* (frac "a" "b")) can share its paragraph with text.

  A formula group (align*
    (tformat (table (row (cell "x") (cell "=1"))
                    (row (cell "y") (cell "=2"))))) continues here.
#+end_src

Line breaks inside the group are supported, but a blank line would cross
the paragraph boundary and prevent recognition of that fragment.  These
examples describe source and AST structure, not display placement or numbering.

Fragments are also recognized in direct plain text of anonymous =[fn::...]=
and named =[fn:name:...]= inline footnote definitions.  Org determines the
body and delimiter boundaries.  Discovery does not enter emphasis, links,
code or verbatim objects inside a footnote; an adjacent fragment remains
eligible.  Configured-root candidates that cannot finish within the inline
footnote body, or use unsupported reader punctuation, signal an error rather
than silently becoming literal text.  The ordinary paragraph stop rule above
is unchanged.  STM strings containing brackets or newlines must still obey
Org's footnote grammar; the exporter does not repair footnote delimiters.

Source discovery returns an =org-texmacs-fragment-span=, not an Org node or a
parsed TeXmacs tree.  Parsing that span returns a fresh pseudo tree with the
same root tag as the source.  Its children have Org parent links, but the
root is not attached to the span or paragraph.

| API                                             | Result                                               |
|-------------------------------------------------+------------------------------------------------------|
| =(org-texmacs-fragment-at-point &optional POS)= | Span covering POS (default: point), or nil           |
| =(org-texmacs-fragment-map BEGIN END FUNCTION)= | Callback results for complete spans, in source order |
| =(org-texmacs-fragment-tree SPAN)=              | Independently parsed, Org-compatible TeXmacs tree    |

This self-contained example inspects a span and traverses its tree.  Unlike
block cache hits, repeated fragment tree calls parse again and return different
tree objects:

#+name: example-fragment-tree
#+begin_src emacs-lisp
  (progn
    (require 'org-texmacs)
    (with-temp-buffer
      (org-mode)
      (insert "A (math (frac \"1\" \"2\")) B\n")
      (goto-char (point-min))
      (search-forward "(math")
      (let* ((span (org-texmacs-fragment-at-point))
             (tree (org-texmacs-fragment-tree span)))
        (list (org-texmacs-fragment-span-source span)
              (org-element-map tree '(math frac) #'org-element-type)
              (eq tree (org-texmacs-fragment-tree span))))))
  ;; => ("(math (frac \"1\" \"2\"))" (math frac) nil)
#+end_src

Scanning alone does not start TeXmacs:

#+name: example-fragment-map
#+begin_src emacs-lisp
  (progn
    (require 'org-texmacs)
    (with-temp-buffer
      (org-mode)
      (insert "A (math \"x\") B (math (sqrt \"y\")) C\n")
      (org-texmacs-fragment-map (point-min) (point-max)
                              #'org-texmacs-fragment-span-source)))
  ;; => ("(math \"x\")" "(math (sqrt \"y\"))")
#+end_src

Passing =#'org-texmacs-fragment-tree= as the callback instead parses each span.
Callbacks run in the source buffer, with point and narrowing restored after
each call.  They must not edit source, kill or switch the current buffer, or
change its major mode or fragment tag configuration.  Detected changes stop
traversal with an error; completed callback effects are not rolled back.

** Span lifetime and positions
Treat spans and their source strings as read-only.  Accessors such as
=org-texmacs-fragment-span-begin= and =org-texmacs-fragment-span-end= expose the
half-open range =[begin, end)=: begin is included, end is not.  Position and
region arguments must be accessible integer positions in an Org buffer.
Region filtering includes only complete spans; it never truncates a formula.

Pass a span to =org-texmacs-fragment-tree= in its original buffer.  Any character
edit, even elsewhere in the buffer or subsequently undone, invalidates it.
Obtain a fresh span after editing.  Text property changes alone do not
invalidate spans.  Bounds and raw source are checked before parsing and again
after waiting for the worker, so stale results are not returned.

=org-texmacs-fragment-span-tag= records the root name as a string, and
=org-texmacs-fragment-span-tags= records a copied configuration snapshot.
Treat both as read-only.  Obtain fresh spans after changing
=org-texmacs-fragment-tags=: tree calls and map callbacks check the complete
list by value, including order, before and after processing.  No change
history is tracked, so restoring an equal value is accepted.

Scanning treats the current narrowing as the document boundary and never
widens implicitly.  If narrowing cuts into an Org container, context outside
that boundary is not available; widen first when full-document context is
needed.  A previously obtained span must remain fully accessible when parsed.

** Configuring entry tags
The default =org-texmacs-fragment-tags= is:

#+begin_src emacs-lisp
  '("math" "equation" "equation*" "eqnarray" "eqnarray*" "align" "align*"
    "gather" "gather*" "eqsplit" "eqsplit*")
#+end_src

This is a literal, case-sensitive entry list, not a list of all valid TeXmacs
tags.  It accepts dynamic and explicitly buffer-local bindings.  An empty
list disables fragment discovery; duplicates do not duplicate results and
list order does not control matching.  Values must be proper lists of
nonempty strings.  Names start with an ASCII letter and continue with ASCII
letters, digits or ~- _ . * + ? ! : / < > =~.  Reader-escaped names are not
supported; invalid configuration signals =org-texmacs-error= before parsing.

For math-only discovery in the current Org buffer:

#+begin_src emacs-lisp
  (setq-local org-texmacs-fragment-tags '("math"))
#+end_src

Use =setq= for the default in buffers without a local value, or a =let=
binding for a scoped operation.  The package does not automatically mark
this option safe for file-local variables.  Obtain and parse spans under
the same configuration; an old span is not a way to bypass a changed entry list.

This example demonstrates a buffer-local list, a temporary override and
disabled scanning.  Discovery does not parse or start TeXmacs:

#+name: example-fragment-config
#+begin_src emacs-lisp
  (progn
    (require 'org-texmacs)
    (with-temp-buffer
      (org-mode)
      (insert "A (math (sqrt \"x\")) B (equation* \"y\") C\n")
      (setq-local org-texmacs-fragment-tags '("equation*"))
      (list
       (org-texmacs-fragment-map (point-min) (point-max)
                                #'org-texmacs-fragment-span-tag)
       (let ((org-texmacs-fragment-tags '("math")))
         (org-texmacs-fragment-map (point-min) (point-max)
                                  #'org-texmacs-fragment-span-tag))
       (let ((org-texmacs-fragment-tags nil))
         (org-texmacs-fragment-map (point-min) (point-max) #'identity))
       org-texmacs-fragment-tags)))
  ;; => (("equation*") ("math") nil ("equation*"))
#+end_src

Adding a custom entry name only enables discovery.  It does not register a
TeXmacs environment or establish its argument, layout or rendering semantics.
The entry list is not recursive: =sqrt= above remains a child of =math=
without needing its own entry.

** Recognition limits
Configured roots are recognized in paragraph text, including paragraphs in
list items and quote blocks, and direct text of inline footnote bodies.
They need not occupy a whole paragraph or footnote body.  Headline text, table cells, native objects such as emphasis,
link descriptions and code/verbatim, source blocks, and TeXmacs special-block
bodies are excluded.

The entry list does not restrict children inside a fragment, or roots and
contents of a =#+begin_texmacs= block.  Block contents are never split into
fragments, and block parsing and caching do not consult this option.  After
accepting a fragment the scanner skips its interior; an unconfigured outer
tag does not itself hide configured candidates inside it.

Use TeXmacs special blocks for standalone complex content such as tables,
images or code, which are not additional default fragment entry points.
The following example parses paragraph fragments and a block through the
same worker without discovering fragments inside the block:

#+name: example-fragment-block
#+begin_src emacs-lisp
  (progn
    (require 'org-texmacs)
    (with-temp-buffer
      (org-mode)
      (insert "A (math \"x\") B (equation* \"y\")\n\n"
              "A group (align*\n"
              " (tformat (table (row (cell \"x\") (cell \"=1\"))\n"
              "                 (row (cell \"y\") (cell \"=2\"))))) ends here.\n\n"
              "#+begin_texmacs\n(with \"mode\" \"math\" (math \"z\"))\n"
              "#+end_texmacs\n")
      (let ((roots
             (org-texmacs-fragment-map
              (point-min) (point-max)
              (lambda (span)
                (org-element-type (org-texmacs-fragment-tree span))))))
        (goto-char (point-min))
        (search-forward "#+begin_texmacs")
        (list roots
              (let ((org-texmacs-fragment-tags nil))
                (org-element-type (org-texmacs-tree (org-element-at-point))))))))
  ;; => ((math equation* align*) with)
#+end_src

Nested lists, strings, escaped quotes/backslashes and newlines within one
paragraph are supported.  The scanner is not a full Scheme reader: outside
strings, comments and reader punctuation such as =;=, =#=, single quote,
backtick, comma, vertical bar and backslash are unsupported.  An unsupported
or unclosed candidate is not returned, and scanning stops for the remainder
of that paragraph; the next paragraph is scanned normally.  Balanced source
can still be rejected by the worker, for example =(math 1)=.

Fragment spans and trees are derived data only.  Org's native parser is not
extended: it can still interpret =*bold*= or links inside a formula string.
Other Org consumers do not automatically gain TeXmacs boundary semantics.
Source text remains canonical; generic Org parse/interpret is not guaranteed
to reconstruct it character for character.

Each discovery call scans a private copy of the accessible buffer before
region filtering.  There is no fragment cache or incremental synchronization,
and large-document performance has not been validated.

* Embedded STM editing
Loading =org-texmacs= enables Scheme fontification for recognized paragraph
fragments, direct inline footnote fragments and TeXmacs special-block bodies in
existing and new Org buffers.  Font Lock must itself be enabled.  STM regions
use Scheme string and parenthesis syntax; Org link, emphasis and hiding
properties inside them are suppressed.  Other Org text keeps normal behavior.
This is lexical presentation, not STM validation or support for arbitrary
Scheme syntax, evaluation or Org Babel execution.  Export recognition and
native STM parsing are unchanged.

The implementation processes affected paragraph/block contexts rather than
copying the whole document on each edit.  Incomplete STM while typing is not an
export error in the editor.  There is no dedicated command or Customize option.
The internal buffer-local variable =org-texmacs--font-lock-enabled= defaults to
=t=; a =nil= local binding suppresses STM presentation, and setting its default
binding to =nil= suppresses it globally.  Changes to this override or fragment
entry tags schedule normal refontification.  These internal interfaces may
change; disabling presentation restores ordinary Org fontification.

Inside a =texmacs= special block, =C-c '= (=org-edit-special=) opens an Org
source-edit buffer.  =C-c C-c= writes the body back, =C-c C-k= cancels, and
=C-x C-s= uses Org's source-edit save workflow.  Unedited body whitespace is
preserved, including in indented containers.  In the original Org buffer,
=TAB=, line indentation and region indentation use Scheme indentation within
the block body.  Block delimiters remain Org syntax.  These facilities do not
require STM fontification to be enabled and do not enable Babel execution.

The user option =org-texmacs-edit-mode= selects the mode for source editing and
indentation; it defaults to Emacs's bundled =scheme-mode=, with no extra package
dependency.  Selecting =scheme-ts-mode= requires the user to install that mode
and its Scheme Tree-sitter grammar.  Unavailable support produces an explicit
error; the package does not install dependencies or silently fall back.  Existing
edit buffers retain their mode until closed.  This option does not select the
mode used for STM fontification.  Dedicated source editing and indentation
apply to complete TeXmacs special blocks, not paragraph fragments.

* Mathematical-document model construction
Load =(require 'org-texmacs-model)= to construct an independent snapshot from
an already parsed native Org AST and STM trees.  This module does not load the
document lowering layer, export frontend or worker.  Its autoloaded
=org-texmacs-parse-buffer= adapter can construct a complete model from an explicit
Org source buffer, using native STM parsing without document lowering.

#+begin_src emacs-lisp
  (require 'org-texmacs-model)
  (let* ((leaf (copy-sequence "island"))
         (ast (org-element-create
               'org-data nil (org-element-create 'paragraph nil leaf)))
         (model (org-texmacs-model-create
                 ast :islands (list (cons leaf '(math (frac "1" "2")))))))
    (org-texmacs-model-islands model))
#+end_src

=org-texmacs-model-create AST :islands ISLANDS :context CONTEXT= copies the
=org-data= AST, rebuilds parent links and remaps identity-keyed islands to the
owned nodes.  Secondary strings and captions are included.  Each island value
is a parsed STM tree, including a possible atomic string leaf.  Invalid trees,
cycles, multiply owned nodes, detached or duplicate keys, overlapping islands,
deferred properties and opaque runtime objects signal =org-texmacs-model-error=.
The constructor does not scan source text, start a worker, allocate output
references or invoke document lowering.  The caller supplies the island
associations; this entry does not prove source-recognition completeness.

Model validity is independent of the exporter's Org support and of Org
serialization support.  Legal comments, drawers, unused footnotes and excluded
headlines can remain in the AST.  A structurally valid tree at an island can
have a root that current inline recognition would not recognize.  That does
not invalidate the model or trigger implicit source parsing.

The STM tree is authoritative for mathematical content.  Its Org key retains
the wrapper and affiliated structure; old raw mathematical text is not a
fallback value for consumers.  The snapshot has no dependency on its source
buffer's continued existence.  Model accessors return internal read-only
references: callers must not modify any nested strings, lists or vectors.
Read-only structure slots do not enforce deep immutability.

CONTEXT is an explicit plist of resolved syntax/source data.  Its accepted keys
are =:fragment-tags=, =:heading-settings=, =:link-settings=, =:source-file= and
=:resource-base=.  Values are owned without reading ambient settings or files.
The model does not capture export INFO, style, initial environment, bibliography
output or reference allocation.

For buffer construction, =org-texmacs-parse-buffer SOURCE-BUFFER= captures the
complete unnarrowed source and its effective syntax settings.  It restores the
original narrowing before private parsing or native waits, preserves source
text, point and mark, and returns a model independent of the source lifetime.
It does not interpret narrowing as body selection or run export pruning.

#+begin_src emacs-lisp
  (require 'org-texmacs-model)
  (let ((model (org-texmacs-parse-buffer (current-buffer))))
    (org-texmacs-model-islands model))
#+end_src

The adapter recognizes the existing =texmacs=, =equation= and =equation*= raw
blocks and configured paragraph/direct-inline-footnote fragments.  Titles,
captions, emphasis, table cells and code retain ordinary Org interpretation;
STM-looking text in those contexts does not become an island.  Block parameters
and affiliated properties are preserved without applying TeXmacs lowering's
restrictions.  Raw block parsing residue is removed after association; its STM
tree owns the mathematical content.

Native block boundaries follow Org syntax.  An unindented headline ends its
section, so a block opener before that headline cannot enclose text after it.
Indent headline-looking lines inside multiline STM strings when they are meant
to remain block content.  An incomplete block retains ordinary Org structure;
the adapter does not reinterpret its headings as mathematical data.

Comments, arbitrary property drawers, unreferenced footnote definitions,
excluded headlines and other native Org structures remain in the model.
INCLUDE, SETUPFILE and bibliography declarations remain source syntax here;
the adapter does not acquire files, run Babel, export hooks/filters or Cite
processors, format bibliography, resolve output references or invoke lowering.
It parses every recognized island, including those in export-excluded content.
Consequently, invalid STM there also fails model construction.

The syntax snapshot stores bound native heading/TODO/level/priority settings,
the parser's emphasis/list/affiliation/secondary conventions, source radio-link
syntax, registered link names and global/local abbreviations.  Link follow and
export handlers are not captured or invoked as export operations.  Private Org
mode initialization happens before source insertion and without mode hooks.
Regex regeneration stays within private bindings.  This is not a sandbox for
user-defined callbacks used by native Org syntax, such as link abbreviations.

Source text, mode, narrowing, file/resource identity and effective syntax are
checked before and after native waits and before return.  A changed or killed
source signals =org-texmacs-model-error= without rolling back external edits.
Invalid native STM retains =org-texmacs-parse-error= and transport failures retain
=org-texmacs-worker-error=.  This does not change the existing export adapter's
selection, preflight order, bibliography or output contracts.

Existing export inputs reuse this model's ownership machinery.  Their
=org-texmacs-input-model= accessor holds the same owned AST and islands exposed
by the existing input accessors.  Export INFO, exact post-blank mappings and
target settings remain separate.  Source filtering, bibliography, reference
planning, preflight and native parsing retain their existing export route.

* Mathematical-document inspection
=org-texmacs-model-inspect MODEL= returns a detached readable S-expression view.
=org-texmacs-model-display MODEL= pretty-prints that view in a new read-only
buffer and returns the buffer.  Both entries are autoloaded by
=org-texmacs-model= and work on an existing model without source buffers, STM
parsing, document lowering or native output.

#+begin_src emacs-lisp
  (let ((model (org-texmacs-parse-buffer (current-buffer))))
    (org-texmacs-model-inspect model)
    (org-texmacs-model-display model))
#+end_src

Org nodes appear as =(TYPE PROPERTIES CONTENTS...)=, ordinary text stays text,
and islands appear as =(stm TREE)= at their structural positions.  Native block
islands keep wrapper properties and affiliation; their old body is replaced in
the view by the current STM tree.  Supplied node islands also suppress old
body-valued properties such as =:value=, =:raw-value= and secondary body objects,
while keeping affiliated captions.  Parsed secondary strings, including titles,
are expanded as Org objects.  Caption lines appear as
=(:long OBJECTS :short OBJECTS)=.  Parsed titles take precedence over redundant
raw title strings, so old source text cannot duplicate a changed title island.

The view preserves document order, text whitespace and other properties, with
property keys sorted for readability.  It omits parent links, source coordinates
and parser bookkeeping, including cache state.  Unset standard =:post-blank=,
=:structure= and =:true-level= slots are omitted; other explicit =nil= properties
remain visible.  Other property links to AST nodes become
=(org-ref PATH)= instead of recursively expanding the linked node.  Paths use
zero-based indices, for example =(contents 0 :title 1)= or
=(contents 0 :caption 0 :short 0)=; the root path is =nil=.

Invalid ownership, parents or island associations signal
=org-texmacs-model-error= with an AST path; errors validating the whole snapshot
use the root path.  Inspection never silently repairs the original model.
The returned view shares no mutable AST/STM data with the model.  It is a debug
projection, not a persistence format or a structural-equivalence definition.
Display uses a unique buffer even when an existing buffer has the requested
optional name, and removes its new buffer if printing or display fails.

* Structural model operations
=org-texmacs-model-copy MODEL= returns an independent, structurally equivalent
snapshot.  =org-texmacs-model-island MODEL NODE= returns the read-only STM tree
for an island key belonging to that snapshot.  Obtain keys from
=org-texmacs-model-islands=, or use native Org traversal to locate a block.
Ordinary Org nodes, equal copies and keys from another snapshot are not valid
island locators.  Accessor results remain read-only by convention.

=org-texmacs-model-replace-stm MODEL NODE PATH REPLACEMENT= creates a new
snapshot with one STM subtree replaced.  PATH is a proper list of zero-based
child indices, excluding tag symbols; nil replaces the entire island.

#+begin_src emacs-lisp
  (let* ((model (org-texmacs-parse-buffer (current-buffer)))
         (node (caar (org-texmacs-model-islands model)))
         ;; Replace the first child's second child in a suitable STM tree.
         (changed (org-texmacs-model-replace-stm model node '(0 1) '(sqrt "x"))))
    (org-texmacs-model-display changed))
#+end_src

These operations use structured Org and STM data directly, without source
parsing, text serialization, native workers or document lowering.  Copy and
replacement own all mutable AST, STM and syntax-context data, rebuild parents
and island mappings, and remap structural references.  A replacement may be
borrowed from an existing tree; the result owns its own copy.  The original
model and its locators remain valid on success and failure.  Obtain new keys
from the new model; old-model keys cannot address it.

Replacing a root with any structurally valid STM tree, including an atomic
string, produces a valid model.  If the root is not recognized at that Org
position under captured syntax, serialization signals
=org-texmacs-model-serialization-error=.  It never silently uses old source
text instead.  Invalid locators, paths or replacement trees signal
=org-texmacs-model-error=; path diagnostics use AST and STM child paths.

Org text residues and source coordinates retain their original-source meaning
after a replacement.  They do not describe the new mathematical content; use
the authoritative island tree, native node identities and structural paths.
This initial API changes STM content and keeps the Org hierarchy.  Arbitrary
Org node insertion, removal or movement is outside this transformation profile.

* Complete model workflow
This self-contained example parses an Org buffer, replaces the denominator of
an inline fraction, inspects the new model and opens normalized Org output:

#+begin_src emacs-lisp
  (require 'org-texmacs-model)
  (let* ((model
          (with-temp-buffer
            (org-mode)
            (insert "* Example\nThe value is (math (frac \"1\" \"2\")).\n")
            (org-texmacs-parse-buffer (current-buffer))))
         (node (caar (org-texmacs-model-islands model)))
         (changed
          (org-texmacs-model-replace-stm model node '(0 1) '(sqrt "2"))))
    (org-texmacs-model-display changed)
    (pop-to-buffer (org-texmacs-model-to-buffer changed)))
#+end_src

The source buffer has already been destroyed when the transformation runs.
The original model still contains =1/2=; the new model contains =1/sqrt(2)=.
Path =(0 1)= selects the first =math= child, then the second =frac= child.
Parsing and final STM serialization use TeXmacs, while copying, tree access,
replacement and inspection operate directly on the stored structures.

* Normalized Org serialization
=org-texmacs-model-serialize MODEL= returns normalized Org text.
=org-texmacs-model-to-buffer MODEL= creates a new editable Org buffer and returns
it, using a unique optional name (default =*org-texmacs-org*=).  Neither entry
invokes document lowering or export preparation.

#+begin_src emacs-lisp
  (let ((model (org-texmacs-parse-buffer (current-buffer))))
    (org-texmacs-model-serialize model)
    (pop-to-buffer (org-texmacs-model-to-buffer model)))
#+end_src

The first output profile requires the recorded syntax context captured by
=org-texmacs-parse-buffer=.  A model constructed from supplied native structures
must also supply suitable context to serialize; omitting it does not invalidate
the model.  Plain Org strings do not carry all buffer-local syntax settings.
The buffer convenience entry installs the captured syntax, fragment tags, link
names/abbreviations and resource directory before inserting text.  It keeps
currently available link handlers; the model does not retain old handler code.
The new buffer does not visit the original file or run mode hooks, INCLUDE,
SETUPFILE, Babel, Cite processors or export filters.

Supported output includes native headings/sections, paragraphs and common inline
objects, lists, footnotes, keywords, comments, property drawers, static code,
ordinary tables and containers.  STM islands must occupy native
=texmacs=/=equation=/=equation*= blocks or the recognized paragraph/direct-inline-
footnote positions.  Supplied islands in titles, captions or other positions can
remain valid models while their serialization fails explicitly.  Unknown Org
extension types and properties that native Org syntax cannot preserve also fail.

Serialization restores authoritative trees on an independent Org copy and uses
=org-element-interpret-data=.  Block metadata and captions remain attached;
old mathematical source and parsing residue cannot overwrite current trees.
STM output uses TeXmacs's native =texmacs->stm= serializer through a separate
worker operation, with native source round-trip validation.  It escapes actual
newlines, returns and tabs to produce single-line source; leaf contents remain
unchanged when parsed.  Tags that cannot round-trip through native STM source
are rejected.  Unicode string leaves and source-expressible Unicode tag names
are preserved.  Models without islands need no native process.

The generated Org text is parsed privately under the captured syntax to check
structure and island placement, associating already known STM trees without
calling the STM parser again.  The check preserves semantic attributes, order,
object spacing and literal/STM text, while allowing source-coordinate and
element-spacing differences.  This conservative profile can reject additional
structures whose native Org interpretation would change the model.
The independent test comparison and normalization-idempotence checks do not use
the human inspection view as their semantic definition.

Invalid models signal =org-texmacs-model-error=.  Unsupported or lossy output
signals =org-texmacs-model-serialization-error= with an AST path; transport
failures retain =org-texmacs-worker-error=.  Serialization returns no partial
text on failure, and buffer construction starts only after successful output.
An initialization failure removes the newly allocated buffer.

* Standard Org Export integration status
The independent core loop is implemented.  The initial standard backend now
runs through =(org-export-as 'texmacs)= and consumes its prepared AST in the
live export context.  It recognizes configured paragraph/direct-inline-footnote
STM and native =texmacs=/=equation=/=equation*= bodies from the final AST,
including macro, Babel and recursive INCLUDE results.  Org logical exclusions
are projected by identity before STM discovery, and consumed configuration
directives remain represented by their effective INFO values.  Full, subtree,
region, narrowed and visible-only selection, standard options and AST filters
follow Org.  Standard Org Cite can consume structured output from the existing
CSL processor.  Public source preparation and document APIs use the same path.
Unsupported prepared structures fail explicitly.
The three dispatcher commands and five main-module source byte/buffer/new-file
exports, structured preparation/document APIs and deprecated preprocessed/discovery
wrappers share this standard path.  No parallel source preparation is used.

The adapter resolves deferred properties while the export buffer is live,
copies the final tree, and parses complete STM once with TeXmacs.  Its model
owns the Org nodes and island mappings without retaining full INFO or relying
on source positions.  Legal AST filters can insert, delete, move and replace
supported nodes.  Adjacent text leaves can supply synthetic inline STM; a
synthetic native block can supply structured contents or a complete
=:texmacs-source= string property.  That explicit property supplies its native
body, while the Org node retains its type and affiliation.

Standard Org determines the document structure before STM recognition.  The final
prepared, pruned, filtered and Cite-transformed AST is authoritative.  Complete
multiline STM is supported within one effective paragraph, inline footnote or
valid native block.  An island cannot cross a heading, paragraph or block boundary
to find its closing delimiter.  Identifiable incomplete, invalid or unassociated
candidates fail explicitly.  Target-specific =raw= objects remain unsupported.

Preprocessing may expand, rewrite, delete or generate STM.  Valid final STM is
accepted; deleted or transformed original candidates are not restored.  Text such
as INCLUDE, macros, links or citations inside an STM string receives normal Org
processing.  If Org fails, its error propagates; if it produces invalid STM, native
or structural validation fails.  No generic early STM parser or INCLUDE shielding
is installed.  Arbitrary original STM text cannot always be expressed unchanged
in an Org paragraph.  Independent =org-texmacs-parse-buffer=, model operations and
pure document lowering keep their separate existing contracts.

Org Cite owns bibliography acquisition, processor selection and citation/
bibliography processing in this same transaction, after AST filters.  With the
optional =citeproc= package installed, select the existing =csl= processor and a
local CSL style, for example:

#+begin_example
  ,#+bibliography: references.bib
  ,#+cite_export: csl /absolute/path/style.csl
  Text [cite:@key].
  ,#+print_bibliography:
#+end_example

For the TeXmacs backend, the tested CSL processor returns ordinary Org objects
and elements, including bibliography targets, linked citations and rich affixes.
The existing lowerer constructs their native TeXmacs structures.  U+200B
emphasis delimiters stay in the Org model and become native zero-width spacing
when rendering Org text; STM strings remain opaque.  Processor-generated Org
markup is authoritative: for example, the tested Citeproc bracket layout can
leave a bold affix's stars as literal text, while an unwrapped layout preserves
bold.  The backend does not repair processor output or promise every style's
formatting.  No TeXmacs processor, citation-key rewrite, independent bibliography
discovery or serialized STM round trip is added.  Supported output remains bounded by the existing Org
lowering subset; a CSL style that produces unsupported structures fails
explicitly.  =citeproc= is an optional user dependency, not installed by the
normal package wrapper.  The dedicated Cite check supplies it explicitly.

The default =basic= processor is currently unsupported: its citations and
bibliography return target-specific strings that Org wraps as =raw=.  A =raw=
object is target code, not ordinary text or an STM tree.  It is rejected before
native parsing; it is never silently flattened or reparsed as TeXmacs.  Custom
processors may return supported Org elements or secondary strings.  Returning
an arbitrary target string, including a string built through reentrant
=org-export-data=, does not make it structured output.

Reference targets, relative headline levels, numbering and footnote definitions
are queried in the original standard export transaction, then remapped into the
owned input.  Mutable INFO and identity-sensitive caches are not copied into
the model or replayed after worker waits.  This includes definitions outside a
selected body and Org's actual choice among duplicate targets or definition
copies.  Unused footnote copies are not parsed as STM.  Deferred properties are
materialized while live, including conditional getters, without overwriting
ordinary values supplied by AST filters.

TeXmacs lowering generates native labels, references and footnote structures,
reserves STM static labels, and consumes frozen Org headline/TOC numbers.
Repeated notes bind to their first native footnote.  Nested notes, unsupported
target contexts, targets outside rendered structures, or an Org footnote order
that cannot use sequential native counters fail explicitly.  Org itself may
reject missing footnote definitions during preparation even inside an unused
definition.  Pure input construction retains its independent structural rules;
those rules do not replace standard Org target selection.

Standard options and AST filters run through Org.  Node-level string filters
(for example, paragraph or plain-text filters) are currently rejected before
their callbacks execute, including callbacks installed by options/AST filters.
Their modifications are never executed and silently discarded.  Body and final
output filters run on the final serialized text.  This distinction does not
turn string filters into structural STM transformations.

Native =.tm= source contains Cork octets.  The standard return string uses a
reversible ISO-Latin-1 transport, distinct from the exact unibyte native API.
Use the matching coding system for standard file export; Org adds a terminal
newline.  Do not assume UTF-8 file export preserves these native bytes.

#+begin_src emacs-lisp
  (require 'ox-texmacs)
  (org-export-as 'texmacs)
  (let ((org-export-coding-system 'iso-latin-1-unix))
    (org-export-to-file 'texmacs "/absolute/path/output.tm"))
#+end_src

A private per-call result handoff retains owned structures for native consumers
without repeating preparation or reparsing =.tm=.  Native structured output
rejects effective body/final-output filters and Cite finalizers whose string
effects it cannot preserve.  The tested CSL finalizer is allowed because it is
an identity operation for this backend; advised or subsequently replaced
finalizer/format-dispatch definitions are rejected.  Arbitrary callbacks are
not executed to probe compatibility.  Text export runs the selected standard
finalizer once.  Interactive and explicit source byte/file exports share this
preparation/result handoff, including the structured source APIs.  Prepared-input
requests return owned input without forcing document lowering.  Document and PDF
requests lower once; pure lowering can explicitly reject otherwise valid models.

Standard preparation, AST filters, mutable export INFO and Org Cite processing
must retain their export context; an AST-to-buffer round trip does not preserve
it.  The separate standard Cite integration check below uses a pinned current
=org-roam-organize= with a real SQLite database and its normal mode/hooks/advice.
It verifies UUID citation-key changes, dynamic per-export bibliography and INFO
propagation through CSL, native PDF and HTML without an extension adapter.

* Document conversion and native sessions
The document API separates source preparation, pure structural lowering and
native consumers.  A completed document can update an explicit native session,
serialize to =.tm= or render PDF.  The block and fragment APIs remain available
as independent parsing interfaces.

Load =(require 'ox-texmacs)= to register the backend and export commands.
The dispatcher menu requires explicit key configuration before loading; the
core package alone does not register this frontend.  The frontend uses Org
output names and can overwrite writable regular outputs.  Explicit new-file
saving APIs remain exclusive.  Source byte/buffer/file adapters use standard Org
preparation and optional explicit subtree/region selections and Org configuration.
All source adapters require nil =BIBLIOGRAPHY-SOURCES= and use standard Org Cite.
Existing narrowing bounds the accessible source.

The interactive frontend and standard entry use Org preparation and support
=visible-only= within the stated adapter limits.  =body-only= fragments and
async export are rejected before preparation.  Deprecated preprocessed/discovery
variants are thin standard wrappers with the migration contracts below.
Publishing integration and async export are not claimed.
Native PDF regression checks structure/text/reference semantics; it does not
establish GUI layout or general pagination convergence.  Detailed supported and
rejected cases remain part of the API contracts below.

** Preparing a document result
The document API separates prepared input from buffer preparation.
=org-texmacs-document INPUT= lowers an =org-texmacs-input= without reading
buffers, collecting configuration, parsing STM or starting a worker.
Construct one with =org-texmacs-input-create AST INFO :islands ... :post-blanks ...
:style ... :initial ... :source-file ... :resource-base ...=,
or use =org-texmacs-prepare-buffer SOURCE-BUFFER= for standard Org preparation.
Preparation returns owned input without invoking document lowering or formatting;
valid Org structure may still be unsupported by the document consumer.
The constructor requires an already parsed =org-data= snapshot.  Island mappings
must use identities from that AST and contain parsed strees, not STM strings.
It copies the AST and options, rebuilds parent links, and remaps mapping keys.
Deferred properties, cyclic/multiply owned AST nodes, opaque data and detached
or duplicate mappings are rejected.  A formatter remains an opaque function;
its captured mutable state is not frozen.  Omitted =:style= and =:initial=
select =("generic")= and nil without reading ambient Custom values.  Nil INFO selects fixed defaults,
not current buffer settings.  Treat the input and all nested data as read-only.
The constructor does not perform lowering or call a formatter.

For example, this structural conversion requires no source buffer or worker:

#+begin_src emacs-lisp
  (org-texmacs-document
   (org-texmacs-input-create
    (org-element-create 'org-data nil
                        (org-element-create 'paragraph nil "Hello"))
    nil))
#+end_src

=org-texmacs-document-from-buffer= takes a required =SOURCE-BUFFER= argument and reads
its accessible Org body, independently of the caller's current buffer.
The argument must be a live buffer object, not a buffer name or file path.
It rejects non-Org buffers.  Existing narrowing bounds the body; complete source
selection and preparation are managed by Org in a standard export transaction.
The adapter parses the final STM islands with the shared worker, owns input and
lowers it once into a document result:

| Accessor                                    | Result                                                          |
|---------------------------------------------+-----------------------------------------------------------------|
| =org-texmacs-document-body=                 | Text stree rooted at =document=, before native encoding         |
| =org-texmacs-document-style=                | Copied list of TeXmacs style identifiers                        |
| =org-texmacs-document-initial=              | Copied initial trees; literal provenance distinguishes Org text |
| =org-texmacs-document-stm-paths=            | Paths to source-semantic roots (STM and prepared bibliography)  |
| =org-texmacs-document-initial-literal-keys= | Keys of Org-derived literal initial entries                     |
| =org-texmacs-document-source-file=          | Optional copied absolute source file name                       |
| =org-texmacs-document-resource-base=        | Optional copied base for source-relative resources              |
| =org-texmacs-document-file-paths=           | Paths to Org file-link target leaves in the body                |

Paths use zero-based child indices, excluding the tag.  Keep all fields
together and treat the result and all nested data as read-only.  It is not
a native TeXmacs tree, an Org AST, or a complete TeXmacs file document.
The call does not mutate source text or Org's live AST, and does not cache
the result.  It checks for source and relevant configuration changes while
waiting for the worker; call it again after editing.

For the current buffer, use =(org-texmacs-document-current-buffer)=.
This is a thin wrapper around =(org-texmacs-document-from-buffer (current-buffer))=.
Both entry points capture supported settings from the source buffer and
restore the caller's current-buffer context on return or error.  A mere
current-buffer switch while waiting does not invalidate the source snapshot.

Buffer preparation captures the base buffer's file name as source identity and
the explicit source buffer's effective =default-directory= as its resource
base.  A visiting file does not override a customized directory.  Both strings
are captured into the prepared input and document result, expanding home
abbreviations once during preparation.  Changes to either original location
string during conversion invalidate the snapshot even when the text has not
changed.  Indirect buffers use their base buffer's file identity and their own
effective directory.

For a manually prepared input, =:source-file= and =:resource-base= accept
explicit absolute path strings or =nil=.  Omitted values remain unspecified;
pure construction never reads the current buffer to fill them.  Locations are
copied without path expansion, symlink resolution or file access.  Tilde and
relative location strings are rejected.  File-link lowering preserves raw paths
and marks their target leaves in =file-paths=.  The native bridge uses the
captured resource base to translate these leaves in a separate body copy;
source file identity never chooses or overrides that base.

Each call captures native style/initial values, fragment tags and native output
settings.  Org owns parser settings, source options and preparation dependencies;
the prepared input owns their consumed results.  Source text, mode, restriction,
identity, native style/initial or fragment-tag changes reject publication without retry.
Consumed Org settings and dependency files are not re-read by a parallel receipt
system.  Mutable closure state and arbitrary callback effects are not frozen.

Preparation uses private copies, without changing source text properties,
point, mark, modified state or narrowing, or resetting the source's Org cache.
It does not undo edits made by the user while waiting.  The returned document
does not retain its source buffer and remains usable after that buffer dies.
Construction may start the shared worker to parse STM, but does not open a
native session, render content or write an exported document file.

This example returns a document result; it starts TeXmacs to parse its islands:

#+name: example-document
#+begin_src emacs-lisp
  (with-temp-buffer
    (org-mode)
    (insert "#+OPTIONS: toc:nil\n"
            "* 中\n"
            "Text *bold* <alpha> (math \"α <alpha>\") end.\n\n"
            "#+begin_texmacs\n"
            "(with \"mode\" \"math\" (frac \"中\" \"2\"))\n"
            "#+end_texmacs\n")
    (org-texmacs-document-from-buffer (current-buffer)))
#+end_src

Heading text may contain supported emphasis, literal inline code and bare
default citations, but not explicit line breaks.  This is not a general Org
exporter: unsupported links and footnotes, advanced table semantics, other
blocks, unrecognized keywords, drawers and affiliated metadata outside the
object-specific NAME/CAPTION rules below are rejected.
Empty headline titles and =H= values outside 0 through 5 are rejected.
Headings below =H= use the list mapping above.
Fragment discovery can support
contexts that this whole-document conversion does not support.

Formal statements use Org special blocks with recursively converted Org bodies:

#+begin_example
  ,#+begin_statement theorem
  First paragraph with *markup* and (math "x").

  ,#+begin_texmacs
  (equation* (concat "x=" (frac "1" "2")))
  ,#+end_texmacs

  Last paragraph.
  ,#+end_statement
#+end_example

The canonical =statement TYPE= form requires exactly one type token.
=statement_TYPE= and direct =TYPE= block names are aliases and accept no
parameters.  Types are case-insensitive and explicitly limited to =theorem=,
=proposition=, =lemma=, =corollary=, =axiom=, =definition=, =notation=,
=conjecture=, =remark=, =example=, =note=, =warning=, =convention=, =exercise=,
=problem= and =proof=.  =begin_example= remains Org's literal example block;
use =begin_statement example= or =begin_statement_example= for a formal example.
The body may contain the existing supported Org elements and opaque native STM
blocks; paragraph, whitespace and display-math rules are unchanged.

Statement presentation and numbering belong to the native style; the supported
native validation baselines are =generic= and =article=.  Arbitrary installed
styles are not guaranteed to define these environments.  Statements accept one
=NAME= under the reference rules below and a long =CAPTION=, rendered through
native =dueto= after the statement title and before its body.  Repeated caption
lines are joined with spaces and use the existing caption inline subset
(including markup and links).  Explicit empty captions and every explicit short
caption, including =#+CAPTION[]:=, are rejected; =ATTR_*= remains unsupported.
These rules apply to all sixteen statement tags, including formal =example=.
Custom special-block handlers do not gain caption support.

The generated label and =dueto= prefix surround a first =concat= paragraph;
original STM subtrees remain intact.  An empty body or a first block node uses a
separate prefix paragraph.  A prepared input freezes reference identities once;
repeated consumers reuse them, while a new preparation may allocate different
Org references.  Caption text resembling STM is ordinary text.  Standard Org
does not parse caption inline footnotes; supported anonymous inline footnote AST
objects use the existing native conversion and its documented layout limits.

Raw STM equations use =begin_equation= (numbered) or =begin_equation*= (unnumbered):

#+begin_example
  ,#+begin_equation
  (concat "a=" (frac "1" "2"))
  ,#+end_equation

  ,#+begin_equation*
  "x"
  ,#+end_equation*
#+end_example

Each body is exactly one complete STM datum, parsed by TeXmacs and wrapped as
=(equation BODY)= or =(equation* BODY)=.  Strings (including the STM datum =""=)
and any valid stree are accepted; there is no additional mathematical type check
or automatic =math= wrapper.  Native styles own display layout and numbering;
maintained equation PDF checks cover =generic= and =article=.  Formula blocks may
appear in supported recursive containers, including statements.

Standard source export first applies normal Org preparation to these blocks.
Their final effective contents must form one complete native datum; original
whitespace, escapes or Org-looking directives are not protected from preparation.
After recognition, the native tree is opaque to document lowering.  Independent
parsing retains its own source contract.  Block names are case-insensitive;
effective =NAME= is supported.  Parameters, =CAPTION= and =ATTR_*= are unsupported.
Empty or whitespace-only source is rejected before body parsing.  Multiple datums
and malformed STM are rejected by the native reader.  Region or narrowing exports
must contain the complete selected formula block.  These wrappers do not change
the existing =texmacs= block, inline fragment or editing syntax.

Explicit =figure= / =table= wrappers produce native =big-figure= / =big-table=
environments.  Experimental =figure*= / =table*= wrappers select their native
unnumbered variants; they do not mean LaTeX double-column floats.

#+begin_example
  ,#+CAPTION[Short]: A *formatted* table caption
  ,#+begin_table
  | A | B |
  | 1 | 2 |
  ,#+end_table

  ,#+CAPTION: A native figure
  ,#+begin_figure
  ,#+begin_texmacs
  (graphics "" (line (point "0" "0") (point "1" "1")))
  ,#+end_texmacs
  ,#+end_figure
#+end_example

A figure requires exactly one direct =texmacs= block.  A table requires exactly
one direct Org table or =texmacs= block.  Only metadata-free syntactic blank
spacing is ignored: extra prose, comments, keywords, footnote definitions and
additional bodies are rejected using the original structure before context
cleanup.  Excluded wrappers do not cause unrelated structural errors.  Region
and narrowing selections must include the complete wrapper and its affiliated
caption.  The wrappers are Org structure; only the inner STM body is opaque.

Caption belongs to the outer wrapper.  It supports the existing long/short,
markup and link subset, including file-link provenance.  Caption text resembling
STM remains ordinary Org text and does not create native parse requests.
Anonymous inline footnote ASTs use the caption compatibility rules below;
bare default citations use the bibliography rules below.  Targets remain
unsupported.  Omitted caption
passes =""= to the native environment; numbered variants still show their native
Figure/Table number.  One outer =NAME= is accepted.  Explicit empty =#+CAPTION:=, =ATTR_*=,
parameters and inner-body affiliated metadata are rejected.  Native =generic=
and =article= checks cover empty-caption numbering, interleaved starred counters,
real graphics, table layout and saved-document reloads.

Raw STM table bodies accept =table=, =tformat= ending in =table=, or a complete
=tabular= with one =tformat= operand.  Normalization only adds missing outer
=tabular= / =tformat= layers and keeps the original STM root provenance.
=tformat= permits only preceding =twith= (two arguments) and =cwith= (six
arguments), followed by exactly one =table=.  Tables must have nonempty,
rectangular rows of nonempty cells, each cell with exactly one body argument.
Org's actual block boundaries remain authoritative.  In a footnote definition,
a column-zero =[fn:...]= inside a multiline STM string can terminate that
footnote before Org recognizes the nested blocks.  This spelling is unsupported;
no extra text parser reconstructs the missing figure or TeXmacs block.

Cell contents and formatting values are not reinterpreted.  A naked Org table
retains its existing caption, numbering and reference behavior.  These wrappers
do not add image imports or float-placement controls.  Their names and references
follow the object-specific rules below.

The ordinary special-block dispatch is private, with no stable handler API or
registration command.  Its captured handlers must preserve the entire lowered
body exactly once and must not mutate or reuse its descendants elsewhere, or
duplicate source-semantic content by rebuilding it.  The latter obligation is
a callback contract, not a complete runtime sandbox.  Handler functions are
captured per conversion; mutable closure state is not frozen.  Unknown blocks
and invalid handler outputs fail explicitly.  Structural preflight never calls
custom handlers with placeholder STM.  Detectable source-level block errors
are rejected before body STM parse requests; bibliography native requests may
already have occurred.  Content-dependent handler errors are detected during
final lowering.

Ordinary spaces, tabs and soft newlines collapse to one space across Org
inline text boundaries.  Leading whitespace at paragraph/title starts and
after explicit line breaks is suppressed; a final whitespace run remains
one space.  Paragraphs and explicit line breaks remain structural nodes.
Inline code/verbatim does not parse nested markup, but uses the same prose
whitespace rule: it is not a preformatted code block.  Nonbreaking spaces
are not collapsed.  Conversion does not merge adjacent text slots; a slot
may become empty when its whitespace duplicates a preceding slot.

A bare STM paragraph contains exactly one registered island text leaf; every
other direct child must be an ordinary string containing only spaces, tabs,
CR or LF (empty strings are allowed).  No other Org object is permitted.
Such paragraphs emit the complete island directly, without an additional
=concat=; the island's internal tree and text remain unchanged.  Recognition
still uses =org-texmacs-fragment-tags=; no separate display-tag option is added.
This rule applies in ordinary body text, statement and quote/center containers, separate
footnote definitions and later list paragraphs.  Inline footnote bodies use
the same bare rule inside their existing body =document=, including restored
named definitions.  A leading list paragraph keeps its existing
list-marker/=concat= structure and is not promoted.

Other paragraphs keep their existing =concat= and whitespace semantics.
Direct fragment roots =equation=, =eqnarray=, =align=, =gather=, =eqsplit= and
their starred forms are rejected in such paragraphs and non-bare inline
footnote bodies, including leading list paragraphs: use a standalone body
or a TeXmacs special block instead.
The exporter does not split mixed paragraphs automatically or inspect nested
STM to infer display layout.  Ordinary =math= mixtures remain supported;
arbitrary custom-root layout remains governed by TeXmacs.  Native STM parsing
may precede this rejection, but serialization, PDF rendering and output-file
writing do not.  Native tests compare the same root in matched contexts;
different native environments need not share numbering or layout.

Quote blocks use the native =quotation= environment for single paragraphs,
multiple paragraphs and nested supported content.  Center blocks retain the
native =center= environment.  Structural readback alone does not establish
layout correctness; maintained PDF checks cover quotation indentation and
centering against native references in the locked test environment.

Example, fixed-width and source blocks are static preformatted structures.
They lower to =(code (document LINE...))= without parsing inline Org markup or
discovering STM fragments.  Common indentation follows Org's
=org-remove-indentation= behavior; =-i= preserves indentation for example and
source blocks.  The source buffer's =tab-width= is captured in the conversion
snapshot, and tabs are expanded at display columns before native encoding.
Internal blank lines, ordinary spaces, Unicode and literal angle brackets are
preserved; the syntactic final block newline does not create an extra line.

Source language names do not enable highlighting.  Source blocks are never
executed, and noweb, coderef/line-number switches, header parameters and other
dynamic code semantics are rejected instead of being ignored.  Org has already
removed source-protection commas from the parsed =:value= before lowering.

Basic Org pipe tables lower structurally to
=(tabular (tformat FORMATTING... (table (row (cell BODY) ...)...)))=.
Cells use the same inline subset as other text contexts, including markup,
literal inline code and self-contained URI links.  Empty cells remain empty
=cell= bodies.  Fragment discovery does not enter table cells, so STM-looking
text remains ordinary literal text.

Tables must contain at least one rectangular data row with at least one cell.
Org rule rows become =1ln= top or bottom borders on adjacent TeXmacs rows; a
rule separating the first row group preserves the visible header boundary
without implicitly making header contents bold.  Leading and trailing rules
are supported, but consecutive rules are rejected because their multiplicity
has no lossless mapping in this subset.

Standard export freezes Org's column alignment queries before copying the
prepared tree.  This retains alignment cookies even when Org excludes their
control row from output, and applies Org's numeric-column inference when no
cookie overrides it.  Pure lowering uses those saved values without querying
live Org state.  Width cookies remain unsupported and fail explicitly.

Independent, explicitly constructed inputs use the stricter alignment contract below.
Standard source APIs use Org alignment queries, including numeric inference and
Org control-row removal; width cookies remain unsupported.
A table may have one independent alignment-format row anywhere in its body:

#+begin_example
  | <l>  | <c>   | <r>  |
  | Name | Score | Rank |
  |------+-------+------|
  | A    | 95    | 1    |
#+end_example

Every cell of that row must contain exactly =<l>=, =<c>= or =<r>=, with optional
surrounding whitespace, and its column count must match the data rows.  It sets
native =cell-halign= for each complete column and is omitted from output and
border coordinates.  Multiple format rows are rejected even if identical;
partial declarations and cookies mixed with data are unsupported.  Tables without
a format row use native alignment; numerical content does not enable
automatic alignment inference.  Removing the format row does not repair the
remaining table: missing data or consecutive rules still fail.

=#+TBLFM=, width cookies such as =<10>= / =<r10>=, other special control rows or
columns, merged/grouped cells, non-Org table types and ragged rows are rejected
rather than approximated.

Basic tables accept =#+NAME:= and =#+CAPTION:=.  A captioned table becomes
=(big-table TABULAR CAPTION)=; TeXmacs supplies its table counter and caption
layout.  Multiple caption lines are joined with spaces.  Optional short
captions use =caption-detailed= with long and short bodies.  Captions retain
the supported inline text/markup, bare default citations and URI/internal/file
links; STM fragment discovery does not enter captions.  Their literal text
uses ordinary Org encoding.  Other affiliated keywords, repeated names and
empty captions are explicit errors.

Standard Org 9.8.10 does not parse =[fn::...]= in captions as a footnote;
it remains ordinary caption text.  If an independent model or explicit input constructor
supplies an anonymous inline =footnote-reference= AST, both long and short
captions can convert it using the existing =(footnote (document ...))= mapping.
This applies to naked Org tables and all four figure/table wrappers.  Named
references, named inline definitions and nested notes remain unsupported there.
Caption text and note bodies do not acquire STM fragment discovery.
Standard source export does not support caption footnote nodes, including nodes
created by a parser extension or AST filter. They are explicitly rejected after
effective exclusions, before native parsing. This withdraws the earlier extended
source-adapter compatibility; independent model and pure lowering support remains.
No caption parser extension or native layout repair is provided by this backend.

This is AST compatibility, not complete caption footnote typesetting support.
TeXmacs 2.1.5 =generic= / =article= checks show caption markers while footnote
bodies disappear in the native table layout, and caption directory writes can
consume extra footnote numbers.  GUI/PDF visibility, numbering, directory entries
and page placement are not guaranteed.  The exporter preserves the native AST;
it does not split notes into separate references/anchors or predict float layout.
The test-only Org patch and isolated check live together in
=tests/caption-inline-footnotes/=.  They exercise independent parsing, native lowering and standard source rejection;
the default package, default ERT and normal installation still use stock Org and
neither include nor activate the patch.

Fuzzy links resolve named tables before headline titles.  Referenced captioned
tables place their private label inside the caption, after the native table
counter binding; undescribed links use =reference= and described links use
=hlink=.  An uncaptioned named table has an invisible anchor and requires a
link description.  No table number is invented for it.  Ambiguous referenced
names or collisions with dedicated targets fail explicitly.  Maintained native
PDF checks cover two caption counters, displayed references and caption geometry
against an independent native reference; arbitrary styles and pagination remain
outside this bounded verification.

These rules apply while lowering Org nodes, not as a rewrite of the final
TeXmacs tree.  STM islands remain opaque and unchanged, including their
whitespace.  The source buffer and raw STM extraction are unchanged.

Org's parsed =unordered=, =ordered= and =descriptive= list types map to
=itemize=, =enumerate= and =description=.  Each TeXmacs list contains one
body =document=; =item= or =item*= starts the first paragraph of each item,
while later paragraphs and nested lists remain separate body children.
Description terms use =item*= and the supported inline subset; an untagged
item in the same list uses =item=.  STM discovery remains limited to item
body paragraphs and does not scan description terms.
Checkboxes and explicit =[@N]= counters are rejected.

=quote= and =center= each contain a body =document=, preserving multiple
paragraphs, nested supported lists and TeXmacs islands as structural children.

URI links support =http=, =https=, =mailto=, =ftp= and =ftps=, including
bracket, angle and plain Org links.  Admission uses Org's parsed link type
case-insensitively, preserving its spelling in the target.  Descriptions
may contain supported inline markup; without a description the URI is
displayed.  Targets are assembled from Org's type/path without additional
escaping or prose whitespace normalization.  Conversion does not open or
download targets, invoke export handlers, or embed linked images.
Same-document =[[#CUSTOM_ID]]=, =[[id:ID]]=, =[[*Headline]]= and fuzzy
=[[Headline]]= links in body text and headline titles resolve against visible
headings in the prepared AST.  Fuzzy links also resolve =<<dedicated targets>>=
directly in paragraphs, which take precedence over same-named headings.
Explicit descriptions become internal =hlink= bodies;
links without descriptions become TeXmacs =reference= nodes.  Resolution uses
Org search-cell matching and priorities within the owned effective document.
Named objects and dedicated targets take precedence over headline titles;
multiple distinct matches at the effective priority are errors for used links.
Missing targets fail explicitly.  No source buffer or global Org ID database is
queried.  Named basic tables retain the caption rules above; cross-file IDs,
plain-text search fallback and other protocols remain unsupported.

Statements (including =proof=), =equation= / =equation*=, the four figure/table
wrappers and ordinary =texmacs= blocks accept exactly one nonempty =#+NAME=.
Every such named block gets a label, including unreferenced and unnumbered
objects.  Custom handlers do not acquire NAME support.  Figure/table identity
belongs to the outer wrapper; affiliated metadata on its inner body is rejected.
Repeated NAME declarations on one object are errors; separate objects may share
an unused name, but a link matching both is ambiguous.  Region/narrowing exports
must include the NAME and the complete block, and excluded objects do not supply
targets or cause unrelated metadata errors.

#+begin_example
  See [[eq:main]] or [[eq:main][the main equation]].

  ,#+NAME: eq:main
  ,#+begin_equation
  (frac "1" "2")
  ,#+end_equation
#+end_example

Org allocates internal references once during preparation.  Named labels use
=org-texmacs-SLUG-ORGREFERENCE=; unnamed targets omit the slug.  Slugs lowercase
ASCII capitals, retain ASCII letters/digits and replace each other character
with one underscore; underscores are neither compressed nor trimmed.  Slugs
are readable decoration, not matching keys.  Known static label collisions are
avoided before freezing; unresolved or later collisions are explicit errors.
IDs are consistent within a prepared snapshot and its repeated lowering, but
independent exports need not produce identical IDs or file bytes.

Labels are placed inside equation/statement scope and inside figure/table
caption scope, including absent captions.  A named ordinary STM block instead
uses an external =surround= weak anchor for the whole block.  Its contents stay
opaque; the anchor does not identify or promise the number of an internal native
object.  TeXmacs determines all reference text, including unnumbered environments:
the exporter accepts structural references without judging their displayed value.
Native placement/readback/PDF-link checks cover the pinned =generic= and =article=
styles; arbitrary STM roots and other installed styles have no universal layout
guarantee.  No counter, float-layout or caption-footnote workaround is inserted.
Internal links in document metadata and =ALT_TITLE= remain outside this node.

Plain local file links, including implicit =[[./notes.org]]= and absolute
file links, are supported in body text.  A description becomes the =hlink=
display body; otherwise the raw path is displayed.  The document body retains
the raw path, while =file-paths= identifies its target leaf with zero-based
child indices.  These paths remain separate from STM provenance and propagate
through supported inline and block containers.  Relative paths require an
explicit captured =resource-base=; absolute paths need no implicit base.

The native bridge translates only marked file targets on its own body copy,
then applies ordinary literal native encoding.  The captured
=org-texmacs-link-org-files-as-pdf= setting defaults to =t=: terminal =.org=
suffixes become =.pdf= without case sensitivity.  Set it to =nil= to retain
the original suffix.  This applies to PDF, native =.tm= and session consumers;
labels, URI links and authored STM links remain unchanged.  Other suffixes,
including =.org.gpg=, are not converted.

Native =.tm= and session consumers resolve relative targets into absolute system
paths using the captured source base.  PDF consumers instead preserve relative
paths by default.  Setting =org-texmacs-pdf-file-links-as-absolute= to =t= restores
source-based absolute resolution for PDF only.  Absolute targets remain absolute.
Both booleans are captured during document preparation; changing them later does
not alter a prepared input or completed document.  Pure AST inputs use fixed
defaults unless their INFO supplies =:texmacs-pdf-file-links-as-absolute= or
=:texmacs-link-org-files-as-pdf=.  The structural body always retains raw targets.

The bridge does not open or inspect resources, inline images, or consult the
caller's current directory.  The original document remains unchanged.  File searches
such as =file:notes.org::#target=, application hints, tilde targets, remote
resources, and file links in titles/metadata are unsupported.  Native string
navigation also rejects targets containing =#=, =?=, =*=, =$=, =|=, backslash,
or square brackets, because these may be interpreted as navigation or URL
syntax.  Such paths can remain in a structural result but fail native preflight.

Anonymous inline footnotes such as =[fn::A note]= are supported as
direct paragraph children and in the caption AST subset described above.
Their bodies support ordinary inline markup,
URI/internal/file links and explicit line breaks, with independent prose whitespace
normalization.  Empty bodies are represented by an empty text slot.
Named references such as =[fn:note]= accept either =[fn:note:Inline body]=
or a separate =[fn:note] Body= definition.  A definition can follow its first
reference.  The first reference emits the body with a generated label;
later references emit a superscript reference to the same label.  Separate
definitions support the documented paragraph, list, container, static block
and table subset.  Unreferenced separate definitions are omitted, including
their worker requests.  Definitions needed after headline filtering are
recovered from the same parsed snapshot; no source-buffer fallback is used.
The source's =org-footnote-section= is captured, and its special heading is
omitted while needed definitions are retained.  Missing or ambiguous named
definitions, nested footnotes and footnotes in headings, emphasis, table
cells or link descriptions are rejected.
Outside captions, direct text in inline definitions and paragraphs in separate definitions use
normal configured fragment discovery.  Inline bodies follow the bare-island
and mixed-display boundaries described above; their STM roots and local file
targets retain provenance and are emitted only at first use.  Definition selection follows Org's standard queries. An outside inline
definition may yield an empty body in a selected scope; the exporter does not
restore it from the full source. Pure lowering uses frozen data without reading
source text.
Adjacent footnotes remain adjacent nodes without added separators or
package-assigned footnote numbers.  Native body round trips do not establish
rendering or numbering correctness.

Standard source export uses Org's link registration and abbreviation semantics.
Register optional schemes such as =ftps= through normal Org configuration. An
unregistered scheme can be parsed as a fuzzy link and produce an Org resolution
error. Consumed link settings are owned without private receipt replay or global
protocol registration. Independent parsing and pure lowering retain their own
contracts; link descriptions gain no STM discovery.

Source preparation uses Org's standard working buffer and parser settings.
File and subtree configuration, selection, macros, INCLUDE, SETUPFILE, Babel and
export hooks follow Org.  Final structures must fit the supported TeXmacs subset.
The independent =org-texmacs-parse-buffer= entry performs model construction
without standard export preparation.

** AST filters and Org Cite
Options and parse-tree filters run in the real =texmacs= export transaction with
normal Org INFO.  Legal insertion, deletion, movement and replacement are allowed,
including positionless synthetic nodes.  There is no citation-key-only filter
restriction.  The final AST is authoritative; STM needs complete input obtainable
from its effective structure or an explicit native-source property.

Configure standard bibliography and =CITE_EXPORT= for the supported CSL processor,
with optional =citeproc= installed.  Acquisition, processor selection, citation
filters and processing belong to Org.  See [[*Standard Org Export integration status][Standard Org Export integration status]]
for processor, raw-output and text-filter boundaries.  Do not supply BibTeX text
snapshots to source APIs.  Pure document construction and lowering invoke no
export callbacks or bibliography acquisition.

** Explicit native bibliography inputs
Pure callers may provide already parsed native bibliography trees through
=:bibliography= to =org-texmacs-input-create=.  They also supply complete owned
native formatting context, including =:texmacs-bibliography-declarations= and
=:texmacs-bibliography-output=.  Lowering validates native entries, labels and
references without file reads or formatting.  This constructor protocol is
separate from standard source Org Cite.  No source wrapper acquires or formats
bibliographies through the retired native preparation provider.

Disable unwanted fields with standard options.  Org owns option recognition,

*** Document information and abstracts
Document preparation accepts =TITLE=, =SUBTITLE=, =AUTHOR=, =EMAIL=, =DATE=,
=LANGUAGE=, =KEYWORDS=, =DESCRIPTION= and =CREATOR=, including their external
plist keys and subtree =EXPORT_*= properties.  Title, subtitle, author and date
are parsed Org inline objects; other fields are ordinary text, without inline
markup or STM discovery.  Subtitle uses =doc-subtitle= and shares the =title=
visibility option.  Email uses =author-email=, with an independent =email=
option; it can appear without a name.  Hidden information alone does not create
a title block.  Enabling =creator:t= adds =doc-note= with a =Created by:= label
and the effective creator string, using Org's plain generator default.

Repeated title/subtitle/author/date declarations use Org's parsed, space-joined
values, without guessing separate authors.  EMAIL and LANGUAGE use the last
value; CREATOR uses the first.  DESCRIPTION follows ox-html's plain-text
newline joining.  KEYWORDS uses plain space joining for its effective value,
without token splitting, deduplication or inferred commas.  Empty declarations
follow the corresponding Org collection rule, rather than uniformly clearing a
field; explicit nil external values remain distinct from omitted keys.

Each =abstract= block lowers recursively into its own
=abstract-data(abstract(document ...))=, including an empty block.  Multiple
abstracts, ordinary paragraphs and keyword declarations retain source order.
Abstract parameters and NAME/CAPTION metadata are unsupported; an abstract is
not a mathematical statement environment or a named reference target.

In whole-document export, each =#+KEYWORDS= declaration produces an independent
=abstract-keywords= at its source position.  No nearby-abstract ownership is
inferred, and no empty abstract wrapper is fabricated.  In subtree or region
export, the effective keywords appear once before the selected body, after the
title and TOC.  =EXPORT_KEYWORDS= replaces the file values completely; without
that property, the file values are inherited and space-joined.  When selection
filtering removes every declaration position, the effective value also appears
once before the body.  External keywords are a fallback when no file value
exists.  This positional whole-document presentation differs from HTML/LaTeX's
metadata-only keyword presentation.

DESCRIPTION becomes hidden initial =global-subject=, retained in the serialized
=.tm= document and exported as PDF Subject.  It never becomes an abstract or a
visible paragraph.  Its text, including =<alpha>=, quotes and ampersands, is
encoded literally at the native boundary.  The document result records these
Org-derived initial entries in read-only =initial-literal-keys=; unmarked,
explicit native initial values retain their existing source notation semantics.

Standard source export projects Org's effective language and description into
the native initial environment. These values override corresponding native
entries, including Org's default language. Effective nil/empty values clear that
entry, including an absent description; other initial entries remain. Org owns
file/external/subtree precedence. Pure inputs retain native defaults for metadata
fields omitted from their explicit INFO.

The pinned native PDF renderer owns Creator/Producer: a visible CREATOR note

The private =org-texmacs--document-date-timestamp-text= function accepts one
owned raw timestamp string and returns a string, unchanged by default.  Advanced

optional advice strips delimiters only from single active timestamps; ranges

#+begin_src emacs-lisp

  (advice-add 'org-texmacs--document-date-timestamp-text

  ;; Remove the customization with:
  ;; (advice-remove 'org-texmacs--document-date-timestamp-text
  ;;                #'my-org-texmacs-date-display)

This is a private interface, not a stable formatter option or external export
configuration key.  Keep advice side-effect-free; it may run during preflight
and lowering.  Inputs and returned strings are copied.  A string result,
including an empty string, is required.  Each prepared input captures the
function definition; later advice changes affect newly prepared inputs, not the
existing conversion.  Mutable state captured by advice is not frozen.
The rest of a rich date field retains its ordinary inline handling.

The default =org-texmacs-format-headline-function= is
=org-texmacs-format-headline-default-function=.  It joins a strong TODO/DONE
keyword, literal priority cookie, lowered title parts and a literal tag
string, separated by spaces.  One part is returned directly; multiple parts
get one =concat= wrapper without merging adjacent strings.  TODO and DONE
use the same presentation.  All new leaves use Org literal encoding semantics.

Custom formatters receive six arguments:

#+begin_src emacs-lisp
  (todo todo-type priority title-parts tags info)
#+end_src

Disabled metadata arrives as nil, including =todo-type= when TODO is disabled.
=title-parts= contains lowered text strees, not an Org AST or serialized text.
=info= is the owned projected Org context, including the headline presentation
keys and =:texmacs-format-headline-function=.  Return one text stree;
it is validated and copied into the sectioning node's sole title child.
The formatter cannot choose the enclosing sectioning level through its return
value.  Treat inputs as read-only and prefer a side-effect-free function.
The package's default formatter is side-effect-free; custom function side
effects are the caller's responsibility.  Preflight and final lowering may
both invoke it, with no guaranteed invocation count.
Both calls run outside the private link parser bindings, so normal Org parsing
in a formatter does not inherit the conversion's temporary link syntax.

Output options and the selected formatter are fixed for one conversion;
changes affect the next conversion.  Source text and effective parser
settings still undergo the consistency checks described above.

Headline levels are relative to the shallowest retained headline, following
Org export structure rather than raw star count.  The first five visible
levels map to =section= through =subparagraph=.  =num= selects the deepest
numbered level, with starred section tags beyond it; =UNNUMBERED= also selects
a starred tag.  Headlines below =H= become nested =itemize= bodies, preserving
their own contents and descendants.  Headline property drawers may contain
=UNNUMBERED=, =ALT_TITLE=, =CUSTOM_ID= and =ID=; other keys remain unsupported.

A non-nil =toc= option emits a leading static
=(table-of-contents "org-texmacs-toc" (document ...))= when at least one
filtered headline is eligible.  Its entries use =toc-1= through =toc-5= with
an internal =hlink= title and =pageref=.  =toc:N= limits the depth and cannot
exceed =H=.  Numbered headings receive dot-separated numbers computed from the
same filtered tree and =num= policy; other entries remain unnumbered.
=UNNUMBERED: notoc= excludes an entry without removing its body heading, while
other unnumbered headings remain in the TOC.  Parsed =ALT_TITLE= rich objects
replace the TOC title only.  The headline formatter is also used for TOC
titles, with tags omitted under =tags:not-in-toc=.

Each entry targets a deterministic =org-texmacs-toc-N= label placed directly
after its body heading.  Allocation skips statically named =label= nodes in
visible STM islands.  TOC and resolved source links use distinct private label
namespaces.  =pageref= values remain structural references;
the body constructor does not paginate the document or precompute page numbers.

** Complete native document serialization
=org-texmacs-document-serialize DOCUMENT= consumes a completed document result
and returns a complete =.tm= document as an unibyte string of native output
bytes.  It constructs the =TeXmacs= version header from the running worker,
the explicit style tuple and body, and an =initial= collection when nonempty.
It uses TeXmacs's native =serialize-texmacs= directly on the structured tree.
No output file or live session is created.  An existing
session is neither read nor updated; the shared worker may start or be reused.

#+name: example-serialization
#+begin_src emacs-lisp
  (let ((document (with-temp-buffer
                    (org-mode)
                    (insert "Hello *TeXmacs*.\n")
                    (org-texmacs-document-from-buffer (current-buffer)))))
    (org-texmacs-document-serialize document))
#+end_src

The consumer validates and encodes the explicit document fields once, using
the same literal/STM provenance as native sessions.  Marked file links become
absolute system paths against the captured source resource base; an eventual
save directory does not change their targets.  Native STM links are untouched.
Style names and initial keys remain identifiers, and initial values use native
source semantics.  The original document result remains unchanged.

Preserve the returned bytes with =no-conversion= if a separate caller chooses
to write them.  Do not decode them as UTF-8, re-encode them as document text or
replace the native header with the package version.  Preflight and encoding
errors preserve a healthy worker; serialization failures signal
=org-texmacs-serialization-error=.  Invalid response payloads stop the worker.
The serializer does not collect live reference tables, attachments or auxiliary
typesetter state.  It does not paginate, resolve displayed reference values,
save files, integrate an Org exporter or render PDF/preview.

** Saving a new native document file
=org-texmacs-document-save DOCUMENT FILE= serializes a completed document
result and writes the exact native bytes to an explicit absolute local path.
It returns a copied destination path.  The parent directory must already exist;
relative/remote/tilde paths and directory-only names are rejected.  Existing
files, directories and symlinks are rejected, including dangling symlinks.
Exclusive creation checks collisions at the actual open, so a target created
during serialization is also preserved.

#+begin_src emacs-lisp
  (org-texmacs-document-save document "/absolute/output/new-document.tm")
#+end_src

The destination does not choose the format or redefine source-relative links.
Serialization finishes before the output is opened.  The writer uses
=no-conversion= in a private unibyte buffer, without buffer file formats,
write annotations or file-name handlers.  It does not visit the output, create
directories or update a native session.  It copies FILE before worker waits.

Serialization failures create no output.  Filesystem errors propagate as
standard Emacs file errors; a write failure can leave a newly created partial
file for the caller to inspect.  This API creates new files; it
does not provide atomic content publication, replacement, backups, an export
frontend or rendering.

** Exporting an explicit Org source buffer
=org-texmacs-export-texmacs-from-buffer SOURCE-BUFFER &optional BIBLIOGRAPHY-SOURCES SUBTREE-POSITION REGION EXT-PLIST=
returns final native =.tm= bytes from an explicit live Org buffer object.
=org-texmacs-export-to-texmacs-file SOURCE-BUFFER FILE &optional BIBLIOGRAPHY-SOURCES=
exports to a new absolute local file and returns its copied path.  Both use
one real standard =org-export-as 'texmacs= transaction.  The backend is loaded
at export use if needed; merely loading the core or using independent models
does not register it.  Configure menu keys before the first backend load/use.

#+begin_src emacs-lisp
  (org-texmacs-export-texmacs-from-buffer (current-buffer))
  (org-texmacs-export-to-texmacs-file (current-buffer) "/absolute/output/new-document.tm")
#+end_src

Breaking: =BIBLIOGRAPHY-SOURCES= keeps its argument position but must be nil
for all five source byte/buffer/file exports.  Configure normal Org Cite
bibliography and processor settings instead.  Supplied BibTeX text snapshots
fail before preparation, hooks, Cite or workers; they do not install a private
file reader or fallback processor.  The verified CSL/raw boundaries above apply.

=SUBTREE-POSITION= is an integer in the accessible source; its containing heading
must also be accessible.  =REGION= is a nonempty =(BEGIN . END)= integer pair
within that source.  When both are given, the containing heading at BEGIN must
match the requested subtree's containing heading.  An unmatched combination
fails before preparation instead of collecting separate subtree options manually.
A nil REGION deliberately ignores an ambient active region for these explicit
APIs.  The interactive commands retain Org's normal active-region semantics.
Source point, mark and narrowing are restored; caller buffer state cannot select
a different source.  =visible-only= is available through the standard entry or
interactive commands; these explicit-source signatures have no visibility argument.

=EXT-PLIST= follows standard Org semantics, including parsed secondary metadata
or literal strings.  Mutable option graphs and explicit selections are owned
before hooks or native waits.  Org runs INCLUDE/SETUPFILE, macros/Babel, hooks,
options/AST filters and Cite; it defines their normal reads, warnings and errors.
Final text filters run once before reversible Latin-1-to-native-byte conversion;
nonrepresentable output fails explicitly.  No serialized STM is reparsed.

Source text/mode/restriction/identity and native-setting changes during native
waits reject the export.  Already consumed parser, filter and dependency data
are owned; later changes do not replay preparation or the old provider's receipts.
File export validates/copies the destination first and passes it in INFO without
aliasing the protected write path.  It writes the checked native bytes only after
export succeeds, without an extra newline or conversion.  Source-relative
resources retain their captured base.  Existing destinations are never overwritten;
the exclusive-create and partial-write file-error rules above apply.
For a completed document, independent serialization/save consumers retain that
snapshot's content without running preparation again.

** Explicit-source native byte buffers
=org-texmacs-export-to-buffer SOURCE-BUFFER &optional BIBLIOGRAPHY-SOURCES SUBTREE-POSITION REGION EXT-PLIST=
is a noninteractive Lisp API.  It returns a fresh read-only, unibyte
=special-mode= buffer without displaying it.  Each call creates an independent
result, normally named =*Org TeXmacs Source Export*= with a unique suffix when
needed.  The Lisp caller owns its lifetime and can use =kill-buffer= to clean up.

The buffer contains exact native =.tm= bytes with =no-conversion= coding and
no visiting file.  Mode hooks do not run during initialization; initialization
failure removes only the newly allocated view.  Existing results remain intact.
This is native source for inspection/copying, not rendered TeXmacs preview.

#+begin_src emacs-lisp
  (let ((output (org-texmacs-export-to-buffer source-buffer)))
    (unwind-protect
        (with-current-buffer output (buffer-string))
      (kill-buffer output)))
#+end_src

The main module provides five noninteractive explicit-source export APIs:
=org-texmacs-export-texmacs-from-buffer=, =org-texmacs-export-pdf-from-buffer=,
=org-texmacs-export-to-buffer=, =org-texmacs-export-to-texmacs-file= and
=org-texmacs-export-to-pdf-file=.  They share the standard transaction with the
frontend, while retaining explicit source/selection, fresh-buffer and new-file
policies.  Their =BIBLIOGRAPHY-SOURCES= slot must be nil.

** Native PDF rendering
=org-texmacs-document-pdf DOCUMENT= returns unibyte PDF bytes from a completed
document snapshot.  =org-texmacs-document-save-pdf DOCUMENT FILE= writes those
bytes to a new absolute local file, with the same exclusive creation and
partial-write rules as native document saving.

PDF rendering preserves relative Org file targets by default.  Set
=org-texmacs-pdf-file-links-as-absolute= to =t= before preparation to resolve
them against the captured source resource base.  The independent
=org-texmacs-link-org-files-as-pdf= setting controls =.org= to =.pdf= target
conversion for all native consumers and defaults to =t=.  Neither setting
checks whether the linked file exists or builds it.  Serialized =.tm= files
retain absolute file targets, so re-rendering them in TeXmacs can produce
different file-link targets from direct PDF export.

=org-texmacs-export-pdf-from-buffer SOURCE-BUFFER &optional BIBLIOGRAPHY-SOURCES SUBTREE-POSITION REGION EXT-PLIST=
returns PDF bytes from an explicit Org buffer.
=org-texmacs-export-to-pdf-file SOURCE-BUFFER FILE &optional BIBLIOGRAPHY-SOURCES=
writes them to a new absolute local destination only after preparation's final
consistency check.  Both functions are noninteractive Lisp APIs and use the
standard source selection/options/Cite contract above.  PDF consumes the finished
native document directly, with the verified text-filter/finalizer restrictions;
it does not serialize or reparse =.tm= output.

#+begin_src emacs-lisp
  (org-texmacs-export-to-pdf-file (current-buffer) "/absolute/output/new-document.pdf")
#+end_src

The headless worker installs the structured document directly in a temporary
native buffer, invalidates its layout and forces synchronous typesetting before
printing.  Invalidation alone does not populate the native link information
needed for PDF annotations.  A first native PDF print establishes typeset
reference bindings; another invalidation and forced typesetting resolve their
uses before the final print to the same temporary file.
For ordinary body footnotes, the PDF consumer locally supplies a missing native
destination in compatible TeXmacs =render-footnote*= macros.  The reference value
and numbering stay native.  This applies only to the disposable PDF buffer:
serialized =.tm= documents and existing sessions are unchanged.  Explicit initial
overrides of =footnote=, =render-footnote= or =render-footnote*=, foreign macro
shapes and macros already containing the destination are left alone.  Native
=generic= / =article= tests cover anonymous, named and repeated notes, both link
directions, cross-page references and rendering-error recovery.  This does not
repair the caption-footnote layout limitations described above.
It does not serialize and reparse a =.tm= intermediary.
An existing public session remains unchanged.  The temporary buffer and PDF
are cleaned up; transport failure removes the worker's private directory.
Font caches follow TeXmacs's normal lifetime.  Rendering errors signal
=org-texmacs-rendering-error= and preserve a healthy worker; cleanup failure or
invalid responses stop it.

The PDF consumer rejects explicit =image=, =include=, =extern=,
=script=, =action=, =eval= and =raw-data= trees.  Native styles and fonts still
use installed TeXmacs resources; custom styles are not sandboxed.  The renderer
does not run bibliography generation or read caller bibliography files.
Maintained installed tests inspect the PDF with Poppler, including heading and
table reference values, literal Unicode text, external URI annotations and
same-document link destinations.  These links use TeXmacs's native PDF exporter;
no separate PDF link layer is added.  PDF semantic regressions also check
anonymous/named/repeated footnote markers and unique bodies, citation groups/
repeated citations, and selected bibliography entries.  They normalize
extracted whitespace and use short fixtures in isolated native configurations;
they do not assert PDF bytes, pixel snapshots or fixed pagination.  Footnote tests
also use test-only =pypdf= to resolve actual destinations and compare their
positions with the corresponding text lines, including nearby zero-width anchors.
The bounded update/print sequence does not guarantee convergence for every
native layout.  GUI preview and visual layout
coverage remain future work.

** Org export dispatcher
The optional frontend always registers the =texmacs= backend and its three
export commands, but has no dispatcher menu by default:

#+begin_src emacs-lisp
  (require 'ox-texmacs)
#+end_src

To add a menu, configure the single =org-texmacs-export-menu-keys= option before
the first =(require 'ox-texmacs)=.  For example:

#+begin_src emacs-lisp
  (setq org-texmacs-export-menu-keys
        '(:prefix ?T :buffer ?T :file ?t :pdf ?p))
  (require 'ox-texmacs)
#+end_src

With this explicit configuration, select =T= in Org's =C-c C-e= menu:

| Keys  | Action                                                  |
|-------+---------------------------------------------------------|
| =T T= | Export to the managed readonly native =.tm= byte buffer |
| =T t= | Export to Org's local =.tm= output path                 |
| =T p= | Export to Org's local PDF output path                   |

=nil= omits only the menu; use =M-x org-texmacs-export-as-texmacs=,
=M-x org-texmacs-export-to-texmacs= or =M-x org-texmacs-export-to-pdf=
directly without configuring keys.

Non-nil configuration must contain exactly =:prefix=, =:buffer=, =:file= and =:pdf=
once each, with graphic single-character keys.  Unicode keys are supported;
whitespace/control/modifier events, =q=, =?=, =#=, =&= and prefix =P= are unavailable.
Three action keys must differ; the prefix can equal an action key.  Existing
backends may share a prefix with disjoint submenu actions.  Conflicting action
keys or an existing direct-action prefix fail at registration.  No default keys
are filled in, and no later-loaded backend collision monitoring is installed.

Menu configuration is read, validated and copied when the module first loads.
Later =setq= or Custom changes do not update the registered menu, and repeated
=require= does not apply them; use a new Emacs session to apply new settings.
There is no automatic watcher, runtime refresh or key reassignment.  =C-c C-e=
itself is not rebound, and menu settings do not change export command semantics.

The corresponding commands are =org-texmacs-export-as-texmacs=,
=org-texmacs-export-to-texmacs= and =org-texmacs-export-to-pdf=.
They accept Org's standard optional arguments =async subtreep visible-only
body-only ext-plist=.  =async= and =body-only= must be nil and fail before
preparation or prompts.  Full buffer, subtree, active region, narrowing and
visible-only selection follow Org's standard semantics.  Selection and mutable
option data are captured before prompts; functions and opaque objects retain
identity.  Standard EXT-PLIST values and priority are interpreted by Org.
The source APIs use the same rules.  Rich metadata accepts Org secondary
objects or literal strings; strings are not reparsed as Org markup.
With =subtreep=, the containing heading must be accessible within the current
narrowing, as required by standard Org export.  Hiding that heading with
narrowing raises Org's subtree selection error rather than widening the source.

File actions use =org-export-output-file-name=: =#+EXPORT_FILE_NAME= and subtree
output properties follow Org's naming rules, with the =.tm= or =.pdf= suffix.
A source without an output name or visiting filename prompts.  Paths use the
captured source directory.  The actual destination is passed in INFO as
=:output-file= without aliasing the protected final write path.

The frontend can overwrite an existing writable regular output at the same
path without a separate confirmation.  It checks local targets before native
conversion and again before writing; directories, symlinks and source-file
aliases are rejected.  It does not create directories.  Conversion and the
source consistency check finish before the output is opened, so a preparation,
rendering or stale-source error preserves an existing output.  Native bytes are
written without encoding conversion or an added newline.  Standard filesystem
errors propagate; write failure can leave partial output.  This ordinary write
policy provides no backups, atomic replacement or target-version concurrency
protection.  The explicit =org-texmacs-document-save= / =-save-pdf= and
=org-texmacs-export-to-texmacs-file= / =-to-pdf-file= APIs still require a new
destination and never permit overwrite.
The buffer action reuses its untouched frontend-owned result, normally named
=*Org TeXmacs Export*=.  If the name is occupied by another buffer, it allocates
a unique alternative and stably reuses that result.  Ownership is checked by
identity and state, not name alone.  User edits, renaming, changing the mode,
visiting a file or otherwise taking over the result end automatic reuse; the next
export creates a new result and preserves the old buffer.  Explicit-source
results never enter frontend management.

Conversion and source checks finish before result replacement.  A
conversion or content-commit error preserves the previous content without a
partial update.  After content commit, display failure keeps a reused buffer
and its new content; display failure on a newly allocated result removes only
that new buffer.  Results remain readonly, unmodified, unibyte =special-mode=
buffers with =no-conversion= coding and no visiting file.  Mode hooks do not run.
=org-export-show-temporary-export-buffer= controls display.  Use =kill-buffer=
to clean up; the next export recreates a closed result.  Closing the Org source
does not delete the result, and no dedicated cleanup command is provided.

Each action performs one real =org-export-as= transaction.  Org runs hooks,
INCLUDE/SETUPFILE, macros/Babel, options, selection, AST filters and Cite for all
scopes.  There is no separate full-document/local preparation route, project
INCLUDE recursion, old protection framework or legacy INCLUDE size/depth budget.
Org defines preparation warnings/errors.  Once preparation has supplied owned
structures, later changes to consumed INCLUDE/bibliography files do not trigger
custom file receipts, rediscovery or a second preparation.  This is not a
filesystem-atomic snapshot; source/native-setting changes still reject results.

The =.tm= consumers run final standard text filters and convert the reversible
ISO-Latin-1 transport to native bytes.  A filter result outside that transport
fails explicitly rather than losing characters; use an AST/options filter for
Unicode document content.  Native PDF consumes the completed document directly,
with the effective text-filter/finalizer compatibility contract described above.
Unsupported node-string filters are rejected before execution.

The old buffer-local =org-texmacs-export-discover-bibliography= flag no longer
controls these commands.  Leave it nil: any non-nil value produces migration
advice before preparation/output prompts.  Configure normal Org Cite bibliography,
processor and style instead; the =basic= raw-output restriction still applies.

#+begin_src emacs-lisp
  (setq-local org-texmacs-export-discover-bibliography nil)
  (org-texmacs-export-to-texmacs)
#+end_src

All structured preparation/document and source byte/buffer/file exports use standard
preparation and require nil =BIBLIOGRAPHY-SOURCES=.  Loading =org-texmacs= alone
does not register the backend; invoking a source export loads it.  No viewer opens.

*** Source configuration and selection
=org-texmacs-prepare-buffer=, =org-texmacs-document-from-buffer= and source byte/
buffer APIs take =SOURCE-BUFFER= followed by optional =BIBLIOGRAPHY-SOURCES=,
=SUBTREE-POSITION=, =REGION= and =EXT-PLIST=.  Bibliography sources must be nil.
=EXT-PLIST= follows standard Org option merging; it is no longer a restricted
whitelist or a private rich-string parser.  Org parses source metadata.  Scalar
rich metadata supplied directly in INFO remains literal; callers can supply
parsed secondary strings for structured metadata.

Mutable option data is copied before conversion; functions and opaque objects
retain identity.  Style/initial values and native output policies use their
TeXmacs settings.  The pure input constructor consumes explicit INFO and fixed
defaults without reading ambient source settings.

*** Narrowed source buffers
Existing narrowing is the outer accessible source boundary.  Org owns selection
and preparation.  Source text, point, mark, narrowing and modified state are
preserved on success and error.  Changes made by callbacks to the original source
are detected where covered by source guards and are not undone.
Interactive commands support =visible-only=; explicit source APIs have no visibility
argument.  Independent model parsing remains separate from these export semantics.

*** Region export
Standard Org export and interactive commands use an active region as the body.
Explicit source APIs use their =REGION= argument: a nonempty =(BEGIN . END)=
integer pair within the accessible range.  Nil ignores an ambient active region.
When both subtree and region are requested, the accessible heading at BEGIN must
match the requested subtree heading.  Unsupported truncated STM fails explicitly.

#+begin_src emacs-lisp
  (org-texmacs-prepare-buffer source-buffer nil nil (cons begin end))
  (org-texmacs-export-texmacs-from-buffer source-buffer nil nil (cons begin end))
#+end_src

*** Subtree export, configuration and dependencies
Toggle subtree scope in the dispatcher or supply a non-nil =subtreep= to a
frontend command.  Explicit source APIs accept =SUBTREE-POSITION=, an integer in
the accessible range.  Org selects the subtree, applies =EXPORT_*= properties,
prepares footnotes and answers target/numbering queries.  TeXmacs lowering still
creates native labels, references, footnotes and numbering bindings.

#+begin_src emacs-lisp
  (org-texmacs-export-to-texmacs nil t)
  (org-texmacs-export-to-pdf nil t)
  (org-texmacs-document-from-buffer source-buffer nil position)
#+end_src

Selection is captured before native waits.  Prepared inputs own the selected Org
structures and STM trees; native consumers do not reconstruct source context,
repeat preprocessing/Cite or reparse serialized =.tm=.  Org target ambiguity and
footnote selection follow its standard rules, replacing the old private full-source
restoration and ambiguity policies.  Unsupported target structures fail at document
lowering; preparation alone is not a target-support validation command.

** Native encoding and lifetime
=org-texmacs-session-open= creates an empty native document buffer and returns
an opaque handle.  Only one session may be active in the shared worker.
=org-texmacs-session-set-document= takes that handle and a document result,
validates and encodes all fields before mutation, then replaces style, explicit
initial environment and body before verifying native readback.  TeXmacs may
normalize the style package list; initial values are compared as an unordered
key/value mapping.  No =.tm=, =.stm= or =.tmml= document intermediate is used.
Closing returns =nil= and leaves the worker available for parsing.

This self-contained example returns =t= after a successful update and closes
the buffer even if the update fails.  It requires that no session is active:

#+name: example-session
#+begin_src emacs-lisp
  (let ((document (with-temp-buffer
                    (org-mode)
                    (insert "Text (math \"α\")\n")
                    (org-texmacs-document-from-buffer (current-buffer)))))
    (let ((session (org-texmacs-session-open)))
      (unwind-protect
          (progn
            (org-texmacs-session-set-document session document)
            t)
        (org-texmacs-session-close session))))
#+end_src

For repeated updates, keep the handle, prepare a new document from the Org
buffer, and call =org-texmacs-session-set-document= again before closing.
There are no automatic edit hooks or incremental updates.  Do not mutate
handle slots.  A second open rejects without replacing the existing session;
repeated close is harmless.  Worker termination invalidates old handles,
which never refer to a new worker's buffer.  Open a new session explicitly.

Encoding depends on provenance, not on guessing from leaf contents:

- Ordinary Org leaves use literal/source-code semantics.  Unicode becomes
  TeXmacs universal encoding; literal =<alpha>= remains literal text.
- STM leaves use TeXmacs source semantics.  Unicode becomes universal
  encoding, while =<alpha>= keeps its native symbol meaning.  Write
  =<less>= and =<gtr>= in STM when literal angle brackets are intended.
- Initial environment values also use TeXmacs source semantics for their
  complete strees.  Style names and initial keys are identifiers and are not
  passed through ordinary-body text encoding.

The document result retains STM paths until native encoding is complete.  Pass
the original text document to each update; never feed encoded diagnostic output
back as text.  The native path rejects =raw-data=.  Preserving other STM tags
does not validate their arity, character names, mathematical meaning or layout.

Preflight and encoding errors leave the previous document state intact.  Native
update/readback failure discards the session; transport or fatal cleanup
failure stops the worker.  TeXmacs uses an internal headless view so its
document APIs can focus the buffer; this opens no GUI window and is not a
preview.  Successful native readback establishes accepted style, explicit
initial mapping and body structure, not that visual numbering, page references,
auxiliary data or pagination have been resolved.  Serialization, new-file saving
and source export use the independent consumers described above; these operations
do not update a native session.

* Worker behavior and errors
The first parse request or session open starts one shared headless TeXmacs
process.  All buffers use it sequentially,
with one Unix socket connection per synchronous request.
STM source is read as data, never evaluated as Scheme code.  The worker first
requires exactly one complete datum of the supported stree shape, then uses
TeXmacs's parser.  Empty or malformed input is rejected rather than accepted
through TeXmacs parser recovery.

These checks do not validate all tag names or argument counts.  TeXmacs can
accept unknown tags and unusual arities; parser success does not guarantee
mathematical meaning or correct rendering.  Fragment tree calls additionally
require the returned root to match the source span's tag.  Support for starred
and unstarred formula environments means preserving their AST, not providing
equation numbering or validating layout.

Normal use inherits the user's TeXmacs environment and configuration, so the
first start may perform TeXmacs initialization.  Only the socket directory is
temporary.  Tests use separate temporary user and TeXmacs configuration
directories.

| Option                               |   Default | Purpose                        |
|--------------------------------------+-----------+--------------------------------|
| =org-texmacs-program=                | =texmacs= | Executable; absolute under Nix |
| =org-texmacs-worker-start-timeout=   |        60 | Startup wait in seconds        |
| =org-texmacs-worker-request-timeout= |        10 | Response wait in seconds       |

Timeout values must be positive.  Changing =org-texmacs-program= takes effect
after the current worker stops.  Worker exit and Emacs shutdown clean up its
socket directory.  For development, =(org-texmacs--worker-stop)= stops it
explicitly; this is an internal function, not a stable public command.

| Condition                         | Meaning                                                                    |
|-----------------------------------+----------------------------------------------------------------------------|
| =org-texmacs-error=               | Base error; invalid input/configuration, stale span or inaccessible source |
| =org-texmacs-parse-error=         | Invalid STM source or a fragment root tag mismatch                         |
| =org-texmacs-worker-error=        | Startup, communication or response failure                                 |
| =org-texmacs-document-error=      | Unsupported document input or changed source/configuration                 |
| =org-texmacs-encoding-error=      | Invalid native encoding input                                              |
| =org-texmacs-session-error=       | Invalid/stale session or native body operation failure                     |
| =org-texmacs-serialization-error= | Native document serialization failure                                      |
| =org-texmacs-rendering-error=     | Native PDF rendering failure                                               |

All these conditions inherit from =org-texmacs-error=.  Parse errors leave
the worker available for the next request.  Transport failures and request
cancellation stop it; a later parse or session open starts a new worker.
Old session handles stay invalid.  Failed parses are
never cached.  Reentrant requests are rejected; there is no asynchronous queue.

* Development checks
Run from the repository root:

#+begin_src sh
  nix flake check --no-write-lock-file
  nix build --no-link --no-write-lock-file .#org-texmacs
  # Build Emacs with the package and its Lisp dependencies.
  nix build --no-link --no-write-lock-file .#emacs
  # Run one ERT group, or use checks.x86_64-linux.ert for all groups.
  nix build --no-link --no-write-lock-file .#checks.x86_64-linux.ert-core
  # Test the native GoToR renderer independently of Org and font wrappers.
  nix build --no-link --no-write-lock-file .#checks.x86_64-linux.texmacs-with-gotor-support
#+end_src

Checks include byte compilation, package-lint and ERT, including real headless
TeXmacs parsing, worker lifecycle, Org block cache integration, fragment source
boundaries, configuration snapshots and span validity checks.  All 11 default
entry tags have real parser tests, including multi-row formula groups; these
check AST preservation and parent links, not numbering or rendered output.  A missing
TeXmacs executable fails the integration tests instead of skipping them.
Document tests cover structural lowering, source-dependent native encoding,
session updates and failure recovery, with independent native readback
expectations.  Fixed document/session fixtures run against the installed package;
tests do not read or parse this README.  Loading checks require every module
and the adjacent Scheme service file.  The =ert-core= check covers cases without
native execution, =ert-native= covers worker/session/serialization behavior,
=ert-cite= covers CSL and native PDF using test-only =citeproc=, and PDF cases run in two independent checks: =ert-pdf-render= for the PDF
rendering suite and =ert-pdf-document= for document, frontend, preprocessing,
serialization, special-block and worker PDF suites.  Both use the shared native
PDF helpers and inspection tools.  =ert-pdf= aggregates their logs and test names,
rejecting duplicate names across the two groups.  =ert= aggregates =ert-core=,
=ert-native=, =ert-cite= and =ert-pdf= without running their cases again.  Each group can be
built separately; complete flake checks include every group.  Nix may schedule
independent groups concurrently, subject to its build limits.
Nix checks the current system by default.  These commands may download
dependencies and write Nix store/cache data; they do not update the lockfile,
and the build command does not create a =result= link.

The =texmacs-with-gotor-support= check compares original and patched native PDF
actions, including relative/absolute paths, Unicode filenames, URI/internal-link
controls and relocation.  It also checks that the source guard accepts unrelated
renderer changes and rejects changed link dispatch or repeated patching.  It
uses neither org-texmacs nor a font wrapper and does not test GUI navigation.

The default ERT check uses stock Org and includes direct-AST caption-footnote
tests.  The separate =caption-inline-footnotes= check builds the locked Org
9.8.10 with the adjacent test-only patch and checks the distinct pure-model
support and standard source-export rejection boundary.
It does not change =packages.org-texmacs=, =packages.emacs= or the ordinary
development environment.
The legacy multi-extension runner requires caller-supplied pinned extension
sources; the standard Cite runner fetches its declared fixed revision.  Both
remain outside the default flake checks.

The =tests/default.nix= entry uses =personal-nixpkgs='s =tests.mkChecks= to
discover =test-overlay.nix= files and compose their =test.nix= drivers through
=callPackage=.  The optional integration runner has no test overlay and remains
outside that discovery.  Project-specific runtimes, source files and shared test
support enter through explicit Nix arguments; Lisp runners use the supplied
paths without searching parent directories.

The shared =tests/support/mk-ert-check.nix= driver runs ERT in an isolated HOME,
streams combined output to the Nix build log and saves =ert.log= and
=test-names.txt= in each ERT result.  Pipeline failure remains a failed check.
Required test tools must be present in the Nix check environment; missing inputs,
empty suites and duplicate case registrations are errors.  Each executing ERT
check has a 600-second outer timeout; package-lint has 120 seconds.  Existing
per-operation failure and cleanup checks retain their own bounds.

The flake provides =nix fmt= through treefmt to apply the configured formatters.
=nix flake check= also includes the treefmt formatting check.  Org files,
including =README.org= and the compiled examples' sources, and =.gitignore=
participate in formatting.  Patch files, =LICENSE= and =flake.lock= are excluded.

Git flake inputs omit untracked files.  When checking new files before staging,
use an explicit =path:.= flake input, such as
=nix flake check --no-write-lock-file path:.=.
